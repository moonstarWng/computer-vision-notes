# 2 卷积与滤波：从两层循环到 im2col

> **S0 图像基础与工具链 · 第 2 篇**
>
> **为什么学这篇**：图像里 90% 的传统算子都是「邻域加权求和」：模糊、锐化、边缘、去噪、模板匹配，全是它。CNN 的卷积层只是把「权重」从手工设计变成可学习。

## 0. 开始之前：任务与名词

### 0.1 任务：去掉噪声，但不能把划痕也去掉

场景：金属件表面有一条 2 像素宽的划痕，图像有高斯噪声。你要在保留划痕的前提下降噪，然后提取边缘。

**痛点**：

- 不滤波：噪声的梯度比划痕还大，边缘检测全是噪点。
- 滤波太狠：划痕被抹平，漏检。
- 自己写循环：640×480 的图用 Python 两层循环，跑一次几十秒，调参调到崩溃。

**本篇解决哪一步**：把「邻域运算」这件事从定义讲到可运行的高效实现，并给出**选择核、选边界、算代价**的方法。

### 0.2 名词卡片

**卷积（convolution）**
- 一句话：核翻转 180° 后滑动加权求和。
- 公式：`(I * K)(i,j) = Σ_u Σ_v I(i-u, j-v)·K(u,v)`
- 不是：深度学习框架里的 `Conv2d` 实际算的是**互相关**（不翻转）。

**互相关（cross-correlation）**
- 一句话：核不翻转，直接滑动点积。
- 关系：`卷积(I, K) = 互相关(I, rot180(K))`。
- 对称核（高斯、拉普拉斯）两者相同，所以工程里常混用。

**核 / 滤波器（kernel / filter）**
- 一句话：一个小矩阵，决定「看邻域的什么模式」。
- 尺寸通常 3×3、5×5、7×7；越大越模糊、越慢。

**填充（padding）**
- 一句话：在图像四周补像素，控制输出尺寸和边界行为。
- 常见：`valid`（不补）、`same`（补到输出同尺寸）、`full`（补 k−1）。

**步长（stride）**
- 一句话：核每次滑动几个像素。
- `stride=2` 让输出尺寸减半，常用于下采样。

**感受野（receptive field）**
- 一句话：输出一个像素「看到」的输入区域大小。
- 单层 k×k 的感受野是 k；两层 3×3 堆叠是 5×5。

**im2col（image to column）**
- 一句话：把每个滑窗摊平成一行，卷积变成一次矩阵乘法。
- 用在哪：所有深度学习框架的卷积实现。

**可分离核（separable kernel）**
- 一句话：二维核能写成一维列向量 × 一维行向量。
- 例子：高斯核；代价从 `O(k²)` 降到 `O(k)`。

**索贝尔算子（Sobel operator）**
- 一句话：先平滑再差分的 3×3 梯度算子。
- 输出：`Gx`（竖直边缘）、`Gy`（水平边缘）。

**拉普拉斯算子（Laplacian）**
- 一句话：二阶差分，对噪声更敏感，常用来做锐化。

## 1. 直觉：一个小窗口在图上滑

先看一维。信号 `I = [1, 2, 3, 4, 5]`，核 `K = [1, 0, -1]`。

**互相关**：核不翻转，从左边滑到右边：

```
位置 1: 1×1 + 2×0 + 3×(-1) = -2
位置 2: 2×1 + 3×0 + 4×(-1) = -2
位置 3: 3×1 + 4×0 + 5×(-1) = -2
```

结果 `[-2, -2, -2]`，正好是「相邻差」，所以 `[1,0,-1]` 是差分算子。

**卷积**：核先翻转成 `[-1, 0, 1]`，结果符号相反。对对称核没有区别。

二维就是把一维的窗口变成 `k×k` 的方块：

```
        ┌─────────┐
        │ 核 3×3  │   ← 在当前像素周围盖上
        └─────────┘
  图:   ... 逐项相乘，再全部相加 → 输出一个数
        然后窗口向右移 stride 个像素，重复
```

**三个直观结论**：

1. **核决定「看什么」**：全 1 是平均（模糊），`[1,0,-1]` 是差分（边缘），中心大四周负是锐化。
2. **核越大，看的范围越大**，但也越模糊、越慢。
3. **边界没有像素可看**，所以必须决定「补什么」。

## 2. 公式与输出尺寸

### 2.1 二维互相关

```
out[i, j] = Σ_{u=0}^{k-1} Σ_{v=0}^{k-1}  img[i·s + u, j·s + v] · K[u, v]
```

- `i, j`：输出坐标（行、列）
- `s`：步长 stride
- `k`：核边长
- `K[u, v]`：核的第 u 行第 v 列
- 单位：输出和输入同单位（像素值）

**卷积**只多一步：把 `K` 换成 `K[k-1-u, k-1-v]`（上下左右翻转）。

### 2.2 输出尺寸

```
out = floor( (n + 2p - k) / s ) + 1
```

- `n`：输入边长
- `p`：每边补几圈
- `k`：核边长
- `s`：步长

记忆法：**核能完整放下几次**。

真实输出：

```
n=7, k=3, s=1, p=0 -> 5 （5）
n=7, k=3, s=1, p=1 -> 7 （same，仍为 7）
n=7, k=3, s=2, p=1 -> 4 （4，向下取整）
n=8, k=3, s=2, p=1 -> 4 （4）
```

**`same` 的条件**：`p = (k-1)/2`，且 `s=1`。所以 3×3 补 1 圈、5×5 补 2 圈、7×7 补 3 圈。

**除不尽时**：`floor` 会丢掉右边/下边多出来的像素。做「输入输出同尺寸」的网络时，这一点会导致特征图对不齐，必须显式 `padding`。

## 3. 手写实现：先慢，再快

### 3.1 两层循环（教学版）

```python
def correlate2d_naive(img, kernel, stride=1, padding=0):
    if padding:
        img = np.pad(img, padding)
    kh, kw = kernel.shape
    oh = (img.shape[0] - kh) // stride + 1
    ow = (img.shape[1] - kw) // stride + 1
    out = np.zeros((oh, ow))
    for i in range(oh):
        for j in range(ow):
            patch = img[i*stride:i*stride+kh, j*stride:j*stride+kw]
            out[i, j] = np.sum(patch * kernel)
    return out
```

**为什么要手写**：只有自己写过一次，才知道 `stride` 改的是起点、`padding` 改的是画布、翻转改的是核。

### 3.2 和 scipy 对照

```
相关：手写 vs scipy 最大差 = 1.78e-15
卷积：手写 vs scipy 最大差 = 1.78e-15
```

差在 `1e-15` 量级，说明下标、翻转、边界都没写错。

**为什么不用 `==`**：浮点求和的顺序不同，末位会有差异。`np.allclose(..., atol=1e-12)` 才是正确写法。

### 3.3 向量化：sliding_window_view

`np.lib.stride_tricks.sliding_window_view` 把「所有滑窗」变成一个视图，不复制内存：

```python
win = sliding_window_view(img, (k, k))[::stride, ::stride]   # (oh, ow, k, k)
out = np.einsum("ijkl,kl->ij", win, kernel)
```

**`einsum` 读法**：`ijkl,kl->ij` 表示「对 k、l 求和，保留 i、j」，就是逐窗口点积。

### 3.4 im2col：卷积 = 矩阵乘法

```python
cols, (oh, ow) = im2col(img, k, stride, padding)   # (oh*ow, k*k)
out = (cols @ kernel.reshape(-1)).reshape(oh, ow)
```

**为什么快**：矩阵乘法有 BLAS 高度优化（多线程、SIMD、缓存分块），而 Python 循环每次都要解释执行。

真实输出：

```
3×3：循环 vs im2col 最大差 = 3.33e-16
3×3：两层循环 =   16.77 ms，im2col+GEMM =   0.10 ms，加速 164×
31×31：im2col + GEMM      =   6.49 ms
31×31：只循环核（961 次） =   3.13 ms
```

**注意最后两行**：核变大后，im2col 的「展开拷贝」开始占主导，单张灰度图上它不一定比「按核累加」快。真正让 GEMM 胜出的是 **通道数 × batch**：

```
普通卷积: (N·H·W, C·k·k) @ (C·k·k, C_out)
```

`N` 和 `C` 越大，矩阵越「胖」，BLAS 的优势越明显。这就是为什么 GPU 上从不写循环。

## 4. 高斯滤波：为什么能拆成两个一维

### 4.1 公式

二维高斯核：

```
G(x, y) = exp( -(x² + y²) / (2σ²) )
```

- `x, y`：相对中心的整数偏移，单位像素
- `σ`：标准差，决定模糊程度
- 半径通常取 `3σ`（覆盖 99.7% 能量）
- 最后要归一化，让核的和为 1

真实输出（σ=5）：

```
σ=5 的 1D 核长度 : 31 （半径 3σ=15）
核的和           : 1D=1.000000000000  2D=1.000000000000
2D 核中心值      : 0.00639
```

### 4.2 可分离性

```
G(x, y) = exp(-x²/2σ²) · exp(-y²/2σ²) = g(x) · g(y)
```

所以二维卷积 = 先横向一维卷积，再纵向一维卷积：

```
代价：O(H·W·k²)  →  O(H·W·k)
k=31 时，理论省 31 倍
```

真实输出：

```
可分离 vs 2D 卷积（内部）最大差 = 1.11e-16
31×31：可分离 = 0.34 ms，2D im2col = 16.84 ms，加速 49.5×
```

**工程含义**：实时系统里，大核高斯一律用可分离实现；`cv2.GaussianBlur` 内部也这么做。

### 4.3 σ 和「模糊程度」的关系

| σ | 3σ 半径 | 效果 |
|---|---|---|
| 0.5 | 2 | 几乎不变，只去极细噪声 |
| 1.0 | 3 | 轻微模糊 |
| 2.0 | 6 | 明显模糊，边缘变宽 |
| 5.0 | 15 | 重度模糊，只剩大结构 |

**选择原则**：噪声尺度 < 目标尺度。划痕宽 2 px，σ 就不要超过 1；否则划痕和噪声一起没。

## 5. 一阶与二阶：Sobel、Laplacian

### 5.1 Sobel

```
Gx = [[-1, 0, 1],      Gy = Gx.T
      [-2, 0, 2],
      [-1, 0, 1]]
```

**拆开看**：

```
Gx = [1, 2, 1]ᵀ ⊗ [-1, 0, 1]
     └─ 纵向平滑 ─┘  └─ 横向差分 ─┘
```

所以 Sobel = **先高斯平滑，再求差分**。中间的 2 不是随便写的，它让平滑权重是 `[1,2,1]`，比 Prewitt 的 `[1,1,1]` 更抗噪。

**幅值与方向**：

```
|G| = sqrt(Gx² + Gy²)
θ   = atan2(Gy, Gx)     单位：弧度
```

真实输出（x=120 处竖直阶跃，左 50 右 200）：

```
竖直阶跃在 x=120；内部 Sobel 幅值峰值在 x=119，峰值=600.0
理论上限 = 4×150 = 600（核系数绝对值之和 × 阶跃高度）
边界处的假边缘：x=0 -> 200，x=239 -> 800
（真实阶跃只有 150，补零却造出了 200/800 的梯度）
```

**两个关键点**：

1. 峰值出现在 119/120，即「跨越边界」的位置，而不是边界本身。所以边缘检测输出的是「变化最强的位置」。
2. 边界补零造出了 800 的假边缘 —— 比真实边缘还强。这就是为什么边缘检测前要处理边界，或者把边界裁掉。

### 5.2 Laplacian

```
∇² = [[0, 1, 0],
      [1, -4, 1],
      [0, 1, 0]]
```

- 二阶差分，对**噪声**和**细线**都敏感。
- 不提供方向，只有「这里有没有突变」。
- 常用来做锐化：`sharp = original + α·(original − blur)`，其中 `original − blur` 近似 Laplacian。

### 5.3 三者对比

| 算子 | 阶数 | 抗噪 | 输出 | 用途 |
|---|---|---|---|---|
| Sobel | 一阶 | 中（带平滑） | 幅值 + 方向 | 边缘检测、Canny |
| Prewitt | 一阶 | 较弱 | 幅值 + 方向 | 教学、对比 |
| Scharr | 一阶 | 较强 | 幅值 + 方向 | OpenCV 推荐的小核替代 |
| Laplacian | 二阶 | 弱 | 标量 | 锐化、斑点检测 |

## 6. 边界：补零为什么让边缘变暗

### 6.1 三种常见模式

| 模式 | 做法 | 效果 |
|---|---|---|
| `constant`（补零） | 外面填 0 | 边缘变暗、造出假边缘 |
| `reflect`（镜像） | 以边界为轴对称 | 保持亮度，最常用 |
| `edge`（复制） | 复制最外圈 | 保持亮度，适合大核 |

### 6.2 量化

对一张全 100 的常数图做 9×9 均值滤波：

真实输出：

```
constant : 角点= 30.86  内部=100.00  上边框平均偏差=29.78
reflect  : 角点=100.00  内部=100.00  上边框平均偏差=0.00
edge     : 角点=100.00  内部=100.00  上边框平均偏差=0.00
```

**为什么是 30.86**：

```
9×9 窗口共 81 个位置；
左上角只有 5×5 = 25 个位置落在图内；
25/81 × 100 = 30.86
```

**工业后果**：ROI 贴边做滤波，补零会造出一条「暗边」。后面的阈值/边缘检测把它当成缺陷，产生假报警。**要么用 `reflect`，要么把边界裁掉 3σ 像素。**

## 7. 计算量与 CNN 的关系

### 7.1 直接卷积的代价

```
H × W × k² × C_in × C_out
```

例：`H=W=640, k=3, C_in=64, C_out=64`

```
640 × 640 × 9 × 64 × 64 ≈ 1.5 × 10^10 次乘加
```

**这解释了**：

- 为什么 3×3 是主流（k² 小）。
- 为什么深度可分离卷积能省 8~9 倍。
- 为什么推理要量化到 INT8、要用 TensorRT。

### 7.2 CNN 的卷积层

| 传统滤波 | CNN 卷积层 |
|---|---|
| 核手工设计（高斯、Sobel） | 核通过反向传播学习 |
| 单通道输入输出 | 多通道：`(C_in, k, k, C_out)` |
| 一次卷积 | 加偏置、批归一化、激活 |
| 参数固定 | 参数训练得到 |

**本质没变**：还是「滑窗 + 点积 + 求和」。理解了 S0 的卷积，再看 `nn.Conv2d` 就只是多了通道维和可学习权重。

### 答案

**A1**：`(7 + 2×1 − 3) // 2 + 1 = 6 // 2 + 1 = 3 + 1 = 4`，输出 4×4。

**A2**：高斯核中心对称，旋转 180° 不变，所以相关 = 卷积。第二个核只有右下角为 1，旋转 180° 后变成左上角为 1，峰值位置相差 2 像素（k−1）。

**A3**：半径 `3σ = 9`。高斯在 3σ 外的能量不到 0.3%，再大对结果几乎没影响，只是更慢。

**A6**：都是「邻域加权求和」：卷积用固定/可学习的核，点云用距离权重（如高斯核、双边权重）。区别是点云邻居不规则，没有固定的网格下标，所以要用 KD-Tree / 半径搜索。

### 10.1 主干（1 题）

**Q1. 卷积到底在干什么？为什么说「核决定你看什么」？** ★

**一句话**：拿一个窗口在图上滑，每个位置做一次加权求和——权重长什么样，就看到什么。

**讲开**：

- 核全是正数 → 加权平均（模糊）；`[1,0,-1]` → 差分（边缘）；中间大四周负 → 锐化。
- 核越大，看的范围越大，但也越模糊、越慢（代价 `O(k²)`）。
- 边界没有像素可看，所以必须决定「补什么」——这是后面所有边界坑的来源。
- 现代 CNN 只是把「手工设计核」换成「反向传播学核」，滑窗 + 点积 + 求和的本质没变。

**数字锚点**：`k=31` 的 2D 核有 961 个权重；可分离后只需 2×31 = 62 个乘法，理论省 15.5 倍，实测加速 49.5 倍。

**追问**：「那卷积和全连接的区别？」→ 卷积是**权重共享 + 局部连接**，参数量从 `H·W·k²` 降到 `k²` 量级。

### 10.2 四个必须分清的概念（4 题）

**Q2. 互相关和卷积差在哪？为什么 CNN 里其实算的是相关？** ★

**一句话**：卷积多一步「把核翻转 180°」；对称核看不出区别，不对称核会位移。

**讲开**：

- 互相关：核不翻，直接滑；卷积：核先上下左右翻转再滑。
- 高斯、Sobel 这类中心对称核，翻转后不变，所以两者结果相同——这就是很多人以为「卷积就是相关」的原因。
- 不对称核会暴露差别：峰值位置相差 `k−1` 个像素。
- 深度学习框架的 `conv2d` 实现的是互相关，但名字沿用「卷积」；因为核是学出来的，翻不翻转不影响表达能力。

**数字锚点**：对一个只有右下角为 1 的 3×3 核，相关峰值在 `(1,1)`，卷积峰值在 `(3,3)`，差 2 像素。

**追问**：「面试官追问『那你还敢叫卷积吗？』」→ 敢，但要补一句「工程上叫卷积、数学上是相关，因为核可学习，等价类不变」。

**Q3. Sobel 的 `Gx` 为什么中间一行是 `[-2, 0, 2]`，不是 `[-1, 0, 1]`？** ★★

**一句话**：它是「纵向 `[1,2,1]` 平滑」乘「横向 `[-1,0,1]` 差分」，2 是平滑权重。

**讲开**：

- `Gx = [1,2,1]ᵀ ⊗ [-1,0,1]`：先沿列做一次近似高斯的平滑，再沿行做一阶差分。
- 所以 Sobel 的真实身份是**先平滑再求导**——这正是「导数放大噪声」的解法。
- Prewitt 用 `[1,1,1]`，平滑更弱、抗噪更差；Scharr 用 `[3,10,3]`，旋转对称性更好，OpenCV 在 3×3 时推荐它。
- Laplacian 是二阶导，对噪声更敏感、没有方向信息，主要用来锐化或斑点检测。

**数字锚点**：对「左 50、右 200」的竖直阶跃，Sobel 峰值 = `(1+2+1)×150 = 600`，出现在跨越边界的 `x=119`。

**追问**：「为什么峰值不在 `x=120`？」→ 因为差分算子在看「相邻差」，最大值出现在跨越变化的那一对像素上。

**Q4. 高斯核为什么能拆成两个一维？能快多少？** ★★

**一句话**：因为 `x² + y²` 可以拆成两项，二维高斯就等于两个一维高斯的外积。

**讲开**：

- `G(x,y) = exp(-x²/2σ²) · exp(-y²/2σ²)`，所以二维卷积 = 先横一遍、再竖一遍。
- 代价从 `O(H·W·k²)` 降到 `O(H·W·k)`，`k=31` 时理论省 31 倍。
- 这不只是优化技巧：**它同时是「各向同性」和「可分离」的唯一解**，别的形状做不到两者兼得。
- 工程上大核高斯一律可分离；`cv2.GaussianBlur` 内部也这么做。

**数字锚点**：31×31、σ=5：可分离 0.34 ms，2D im2col 16.84 ms，加速 **49.5×**；两种实现结果最大差 `1.11e-16`。

**追问**：「那 2D 核还有什么用？」→ 各向异性核（沿某方向模糊）、非对称核、或者通道数很大的 GEMM 场景。

**Q5. 一阶导和二阶导做边缘，怎么选？** ★★

**一句话**：一阶（Sobel）给幅值+方向，抗噪中等；二阶（Laplacian）只给「有没有突变」，对噪声更敏感。

**讲开**：

- 一阶导的峰值对应边缘位置；二阶导的**过零点**对应边缘位置。
- 二阶导会放大高频，所以噪声下很容易满天星；一阶导自带 `[1,2,1]` 平滑，稳得多。
- 需要方向（Canny、HOG、轮廓跟踪）→ 必须一阶。
- 需要定位精度或做锐化、斑点检测 → 二阶更合适；锐化公式 `original + α·(original − blur)` 里的 `original − blur` 就近似 Laplacian。

**数字锚点**：同一条阶跃，Sobel 峰值 600、位置 `x=119`；Laplacian 在边缘处出现过零，但噪声 ±5 就能让符号翻转。

**追问**：「LoG 是什么？」→ 先高斯再 Laplacian，把「平滑」和「二阶导」合成一个核，等价于对高斯求二阶导。

### 10.3 三个必踩的坑（3 题）

**Q6. 补零之后做滤波，为什么边缘会变暗、甚至出现假边缘？** ★

**一句话**：补零等于假设「图外是黑的」，窗口一半落在黑区，平均值自然被拉低。

**讲开**：

- 对全 100 的常数图做 9×9 均值滤波：角上只有 5×5=25 个像素落在图内。
- 输出 = `25/81 × 100 = 30.86`，一条暗边就这么被「算」出来了。
- 更糟的是梯度算子：补零会把边界变成「黑→亮」的强阶跃，造出比真实边缘还强的假边缘。
- 解法：用 `reflect`/`edge` 模式，或者把边界裁掉 `3σ` 像素；做测量时更推荐裁掉。

**数字锚点**：9×9 均值、全 100 图：补零角点 30.86，`reflect`/`edge` 角点 100.00；边界平均偏差 29.78 → 0.00。
Sobel 在阶跃图边界造出的假边缘幅值 **800**（真实阶跃只有 150）。

**追问**：「为什么假边缘比真边缘还强？」→ 因为补出来的是「从 0 跳到 200」的完全阶跃，比原图 50→200 的对比度还大。

**Q7. 核忘了归一化会怎样？在 `uint8` 上直接卷积又会怎样？** ★★

**一句话**：不归一化整体变亮/变暗；在 `uint8` 上算，中间结果溢出绕回。

**讲开**：

- 卷积的直流增益 = 核的和；和为 1 才保持平均亮度。忘记归一化，整图乘一个常数。
- `uint8` 的中间结果会溢出：正溢出按 256 取模，负溢出绕回成大正数。
- 正确顺序：`astype(np.float32)` → 卷积 → `np.clip(0,255)` → `astype(np.uint8)`。
- 归一化还会掩盖一个问题：**大部分核本身就不该和为 1**（如 Sobel、Laplacian），这时要清楚自己在算「相对强度」还是「绝对亮度」。

**数字锚点**：σ=5 的高斯核，归一化后 1D 和 2D 的核和都是 `1.000000000000`，2D 核中心值 `0.00639`；不归一化时 31×31 的核和约 157，整图会亮 157 倍（直接溢出成白）。

**追问**：「那 Sobel 的核要不要归一化？」→ 不要，它本来就是要输出梯度幅值；但要知道它的幅值上限是「系数绝对值之和 × 阶跃高度」。

**Q8. 输入 7×7、核 3×3、`stride=2`、`padding=1`，输出多大？** ★★

**一句话**：`(7 + 2×1 − 3) // 2 + 1 = 4`，输出 4×4。

**讲开**：

- 公式 `out = floor((n + 2p − k)/s) + 1`，记忆法是「核能完整放下几次」。
- `padding` 改的是画布，`stride` 改的是起点，`k` 改的是窗口——三者只在这里出现。
- `same`（输入输出同尺寸）的条件是 `p=(k−1)/2` 且 `s=1`：3×3 补 1 圈、5×5 补 2 圈。
- 除不尽时 `floor` 会丢掉右边/下边多出来的像素；做「逐像素对齐」的网络时要显式补边，否则特征图对不齐。

**数字锚点**：`n=7,k=3,s=1,p=0 → 5`；`p=1 → 7`（same）；`s=2,p=1 → 4`；`n=8,k=3,s=2,p=1 → 4`。

**追问**：「输出尺寸对不齐会有什么后果？」→ 特征图与标签错位，训练 loss 降不下去，或者分割边界整体偏一格。

### 10.4 用数字校验（2 题）

**Q9. im2col 一定比直接循环快吗？** ★★

**一句话**：不一定——它赢在「矩阵够胖」，核大、通道少、batch 小时可能更慢。

**讲开**：

- im2col 把每个滑窗复制成一行，再用 BLAS 做 GEMM；BLAS 有 SIMD、多线程、缓存分块。
- 但「展开」本身是拷贝，`k` 大时这份拷贝会吃掉收益。
- 真正决定胜负的是 `C_in × C_out × N`：矩阵越宽，GEMM 越划算——这就是 GPU 上从不写循环的原因。
- 所以「im2col 快」是有条件的结论，不是定律。

**数字锚点**：3×3 单通道：循环 16.77 ms vs im2col 0.10 ms（**164×**）；31×31 单通道：im2col 6.49 ms vs 按核累加 3.13 ms（**反而慢**）。

**追问**：「那 31×31 该用什么？」→ 可分离（如果是高斯）或 FFT；实在不行就按核累加。

**Q10. 一个卷积层的乘加次数怎么估？为什么 3×3 成了主流？** ★★★

**一句话**：`H·W·k²·C_in·C_out`，`k²` 是平方项，所以小核在相同感受野下更省。

**讲开**：

- 感受野要靠层数堆：两个 3×3 顶一个 5×5，但参数从 25 降到 18，还多了一次非线性。
- 深度可分离卷积把 `k²·C_in·C_out` 拆成 `k²·C_in + C_in·C_out`，能省 8~9 倍。
- 这就是为什么推理要量化到 INT8、要用 TensorRT：算力瓶颈在乘加次数上。
- 和传统滤波的关系：核从「手工设计」变成「学习得到」，但滑窗 + 点积 + 求和的代价公式完全一样。

**数字锚点**：`640×640×9×64×64 ≈ 1.5×10^10` 次乘加——单层就上亿级，所以实时系统必须优化。

**追问**：「那 5×5 或 7×7 还有用吗？」→ 有，第一层或大感受野场景；但通常用「3×3 堆叠 + 空洞卷积」替代。

## 11. 坑清单

| # | 坑 | 症状 | 处理 |
|---|---|---|---|
| 1 | 把相关当卷积 | 不对称核结果位移 | 明确用哪个，或翻转核 |
| 2 | 补零后不裁边界 | 边缘变暗、假边缘 | `reflect` 或裁掉 3σ |
| 3 | 核没归一化 | 整体变亮/变暗 | 除以 `kernel.sum()` |
| 4 | `stride` 除不尽 | 右边/下边像素被丢 | 显式 `padding` 或裁剪输入 |
| 5 | 大核用 2D 实现 | 实时性不够 | 可分离（高斯）或 FFT |
| 6 | `uint8` 上做卷积 | 中间结果溢出 | 先转 `float32` |
| 7 | 高斯 σ 大于目标尺度 | 划痕被抹平 | σ ≤ 目标宽度/2 |
| 8 | 忘记 `float32` 的 `-0.0` | 某些比较出错 | 用 `np.allclose` |
