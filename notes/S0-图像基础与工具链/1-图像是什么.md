## 0. 开始之前：任务与名词

### 0.1 任务：相机给了你一张图，可它到底是什么

场景：产线上的相机拍到一个零件，你要写「先灰度化、再阈值、找轮廓」的脚本。

**痛点**：

- 相机 SDK 给的是 `uint8` 的 BGR，你按 RGB 处理，红色零件变成蓝色。
- 你把 `(H, W, 3)` 当成 `(3, H, W)`，`imshow` 直接报错或显示成三条色带。
- 你用「三通道平均」做灰度，绿色和蓝色被判成一样亮，阈值全乱。

**本篇解决哪一步**：把「光 → 电压 → 数字」的链路讲清楚，并给出五个必须记牢的事实：**形状、位深、通道顺序、灰度权重、坐标约定**。

### 0.2 名词卡片

**像素（pixel）**
- 一句话：图像的最小采样单元，一个像素 = 一个或三个数。
- 不是：不是「一个小方块」；它没有物理尺寸，尺寸由标定决定（mm/px）。

**通道（channel）**
- 一句话：同一位置上的一个分量，彩色图通常 3 个（R/G/B）。
- 灰度图可以看成 1 通道；`shape` 是 `(H, W)` 而不是 `(H, W, 1)`。

**位深（bit depth）**
- 一句话：每个通道用多少位表示亮度，8 bit = 256 级。
- 工业相机常见 8/10/12 bit；12 bit 存在 16 位容器里。

**分辨率（resolution）**
- 一句话：`W × H` 个像素。
- 注意：分辨率高不等于精度高，还要看视场和镜头（mm/px 才是精度）。

**灰度 / 亮度（grayscale / luminance）**
- 一句话：把三通道压成一个「看起来多亮」的值。
- 关键：**是加权和，不是平均**。

**色彩空间（color space）**
- 一句话：用一组坐标描述颜色，如 RGB、BGR、HSV、YUV。
- 不是：不是「不同的图」；同一张图可以有多种表示。

**量化（quantization）**
- 一句话：把连续亮度切成有限级。
- 代价：出现色带（banding）；级数越少，PSNR 越低。

**采样 / 混叠（sampling / aliasing）**
- 一句话：采样率不够时，高频信号会被「折叠」成假的低频。
- 表现：细条纹变成粗条纹、摩尔纹、缩略图闪烁。

**峰值信噪比（Peak Signal-to-Noise Ratio，PSNR）**
- 一句话：用 MSE 衡量两图差异，再取对数，单位 dB。
- 不是：不是「画质评分」；它只对同内容、同尺寸的失真有效。

**感兴趣区域（Region of Interest，ROI）**
- 一句话：图里要处理的那一块，通常是切片。
- 注意：切片是视图，改 ROI 会改原图。

## 1. 从光到数：采样 + 量化

相机传感器把光子变成电荷，再变成电压，最后由模数转换器（ADC）变成整数。整个过程只做两件事：

```
空间上：连续场景  --采样-->  一个个像素        （决定 H、W）
亮度上：连续亮度  --量化-->  0~255 的整数      （决定 bit depth）
```

**一个像素的三个数**，就是红、绿、蓝三个滤光片下面的亮度：

```
            ┌─────────────┐
  场景  →   │  R  G  B    │  →  (200, 90, 60)
            └─────────────┘
```

所以「图像」不是一张纸，而是一个函数 `I(x, y) → (r, g, b)` 的离散采样。

## 2. 内存里的图像：形状、类型、字节

### 2.1 三个必须知道的量

```python
img.shape    # (H, W, C) = (高, 宽, 通道)
img.dtype    # uint8
img.nbytes   # H * W * C 字节
```

真实输出（180×240 彩色图）：

```
shape          : (180, 240, 3)
dtype          : uint8  itemsize: 1 字节
像素总数       : 43200  通道数: 3
总字节         : 129600 = 126.6 KB
strides (字节) : (720, 3, 1)  <- (行步长, 列步长, 通道步长)
值域           : [40, 250]
```

**`strides` 是什么**：从当前元素走到「下一行」「下一列」「下一个通道」各要跳过多少字节。

```
下一行   : 720 字节 = W × C = 240 × 3
下一列   :   3 字节 = C
下一通道 :   1 字节
```

**为什么关心**：`strides` 决定了「按行遍历快、按列遍历慢」。更重要的是，它解释了**视图**：切片只是改了 `shape` 和 `strides`，没有复制数据。

### 2.2 一帧图有多大：算一次就有感觉

4K 一帧（1920×1080×3，`uint8`）：

```
1920 × 1080 × 3 = 6,220,800 字节 ≈ 5.93 MB
30 fps          ≈ 178 MB/s
```

**这解释了**：

- 为什么工业相机用 GigE / USB3 / CameraLink，而不是 USB2。
- 为什么实时处理要在 GPU 上做，且尽量在 `uint8` 上完成预处理。
- 为什么「先缩小再处理」不是偷懒，是工程必需。

### 2.3 两种内存布局：HWC 与 CHW

| 布局 | 形状 | 常见于 |
|---|---|---|
| HWC | `(H, W, C)` | OpenCV、PIL、NumPy 默认、TensorFlow |
| CHW | `(C, H, W)` | PyTorch、部分推理引擎 |

转换：

```python
chw = hwc.transpose(2, 0, 1)      # 只改 strides，不复制
hwc = chw.transpose(1, 2, 0)
```

**坑**：`transpose` 之后数组在内存里不是连续的，某些算子会隐式复制，速度下降。需要连续内存时用 `np.ascontiguousarray(...)`。

## 3. 通道顺序：BGR 不是 RGB

OpenCV 的 `imread` 默认返回 **BGR**；matplotlib、PIL 用 **RGB**。

真实输出（同一张图，两种读法）：

```
RGB 通道均值 : R=88.61 G=76.51 B=76.33
BGR 通道均值 : B=76.33 G=76.51 R=88.61
像素 (x=100, y=90) 的 RGB = (60, 80, 200)
同一位置按 BGR 读     = (200, 80, 60) <- 顺序反了
```

**后果链**：

1. 直接 `imshow(bgr)` → 红蓝互换，红色零件显示成蓝色。
2. 用 `0.299R + 0.587G + 0.114B` 算灰度，但把 B 当成了 R → 亮度权重全错。
3. 训练时用 PIL 读（RGB），推理时用 OpenCV 读（BGR）→ 模型精度莫名其妙掉一截。

**修复只有一行**：

```python
rgb = bgr[..., ::-1]          # 或 cv2.cvtColor(bgr, cv2.COLOR_BGR2RGB)
```

`[..., ::-1]` 是视图，不复制；`cvtColor` 会复制，但更快（内存连续）。

**工程建议**：在项目入口统一约定「内部一律 RGB」，所有 IO 在读入后立刻转换，别让 BGR 流进算法层。

## 4. 灰度：加权，不是平均

### 4.1 公式

ITU-R BT.601 的亮度权重：

```
Y = 0.299·R + 0.587·G + 0.114·B
```

- `R/G/B`：0~255 的通道值
- `Y`：0~255 的灰度
- 三个权重和为 1，所以不会改变整体亮度范围

**为什么是这三个数**：人眼视网膜里，对绿光敏感的视锥细胞最多，红光次之，蓝光最少。权重来自人眼的亮度感知实验，不是随便定的。

### 4.2 和「平均」的差距

真实输出：

```
加权 vs 平均：平均差 3.40 / 255，最大差 25.6
纯红: 加权灰度   76.2，平均灰度   85.0
纯绿: 加权灰度  149.7，平均灰度   85.0
纯蓝: 加权灰度   29.1，平均灰度   85.0
```

看纯色就明白了：

| 颜色 | 加权灰度 | 平均灰度 | 人眼感受 |
|---|---|---|---|
| 纯红 (255,0,0) | 76.2 | 85.0 | 中等偏暗 |
| 纯绿 (0,255,0) | **149.7** | 85.0 | 很亮 |
| 纯蓝 (0,0,255) | **29.1** | 85.0 | 很暗 |

平均灰度把三者判成一样亮，和人眼完全不符。**做阈值、做模板匹配、做特征描述之前，灰度化必须用加权。**

### 4.3 601 还是 709

| 标准 | 权重 (R,G,B) | 用于 |
|---|---|---|
| BT.601 | 0.299, 0.587, 0.114 | 标清、OpenCV 默认 |
| BT.709 | 0.2126, 0.7152, 0.0722 | 高清、sRGB |

差异不大（绿色权重更高一点），但**训练和推理要用同一套**，否则特征分布会漂移。

## 5. HSV：把「颜色」和「亮度」拆开

### 5.1 三个分量

```
H（Hue，色相）      : 颜色在色环上的角度，0~1 对应 0°~360°
S（Saturation，饱和度）: 颜色有多纯，0 = 灰，1 = 纯色
V（Value，明度）     : 最亮通道的值，0 = 黑
```

真实输出：

```
H 范围 : [0.000, 0.643]（0~1 对应 0°~360°）
S 范围 : [0.000, 0.778]
V 范围 : [0.157, 0.980]
零件像素 HSV = (0.643, 0.700, 0.784) -> 色相 231°
纯红/绿/蓝色相 : [0.    0.333 0.667] （0, 0.333, 0.667）
```

### 5.2 为什么分割常用 HSV

| 变化 | RGB 里 | HSV 里 |
|---|---|---|
| 开灯/关灯 | R、G、B 一起变 | 主要变 V，H 基本不变 |
| 换个同色零件 | 三个通道都变 | H 不变，S/V 小变 |
| 阴影 | 三通道按比例降 | V 降，H/S 稳定 |

所以「找红色零件」在 HSV 里只需卡一个 H 区间，在 RGB 里要写三个不等式，还要考虑光照。

**注意**：HSV 的 H 在低饱和度/低亮度时不稳定（灰色没有色相），所以工业上常加约束 `S > 0.3 且 V > 0.2`。

## 6. 量化：256 级压到 k 级，损失多少

### 6.1 公式

均匀量化到 `k` 级：

```
step = 255 / (k - 1)
q(x) = round(x / step) · step
```

- `step`：台阶高度
- 最大误差：`step / 2`
- `k = 2` 就是二值图（但这是均匀切，不是阈值分割）

### 6.2 用 PSNR 说话

```
MSE  = mean((a - b)²)
PSNR = 20·log10(255 / sqrt(MSE))   单位 dB
```

真实输出：

```
levels | 台阶 | PSNR(dB) | 最大误差
-------|------|----------|---------
    2  | 255.0 |   11.56  |    90
    4  | 85.0 |   20.28  |    42
    8  | 36.4 |   26.43  |    18
   16  | 17.0 |   33.73  |     8
   32  |  8.2 |   40.79  |     4
```

**怎么读**：

- 每多 1 bit（级数翻倍），PSNR 约涨 6 dB。
- 经验阈值：> 30 dB 肉眼基本看不出；< 20 dB 明显色带。
- 所以「省带宽降位深」要算账：8 bit → 4 bit 省一半，但 PSNR 掉到 20 dB，检测精度可能直接崩。

**工业相机的 10/12 bit 怎么存**：通常放在 `uint16` 里，值域 0~1023 / 0~4095。直接 `astype(uint8)` 会截断高 8 位，必须做线性映射：

```python
u8 = np.clip(img.astype(np.float32) * 255.0 / 4095.0, 0, 255).astype(np.uint8)
```

## 7. 采样：缩小图像为什么必须先滤波

### 7.1 奈奎斯特（Nyquist）条件

要无失真地采样一个信号，采样率必须 **大于** 最高频率的 2 倍：

```
f_s > 2 · f_max
```

不满足时，高频会被「折叠」成低频 —— 这叫**混叠（aliasing）**。

### 7.2 最小例子：周期 4 的细条纹

真实输出：

```
真实均值       : 63.75
直接隔点取样   : 255.00  <- 偏亮 4.0 倍
先均值再取样   : 63.75  <- 和真值一致
```

图 ⑤⑥ 展示了同一件事：

- 原图是周期 4 的黑白细条纹，真实平均亮度 63.75。
- 每隔 4 个像素取一个点，恰好每次都取到白线 → 采样后全是 255。
- 先做 4×4 均值（低通）再取样 → 63.75，和真值一致。

**这就是缩略图算法的核心**：

```python
# 错误：直接切片
small = img[::4, ::4]

# 正确：先低通再采样
small = cv2.resize(img, (w//4, h//4), interpolation=cv2.INTER_AREA)
```

`INTER_AREA` 等价于「按面积平均」，专门用于缩小；`INTER_LINEAR` / `INTER_CUBIC` 用于放大。

**工业后果**：检测细划痕时，如果先粗缩小再找，划痕会被平均掉或变成摩尔纹，漏检率上升。

## 8. 读写、ROI 与坐标

### 8.1 读写的三个坑

```python
import cv2
img = cv2.imread("part.jpg")          # 失败时返回 None，不抛异常！
if img is None:
    raise FileNotFoundError("part.jpg")
```

| 坑 | 表现 | 处理 |
|---|---|---|
| 路径含中文 | `imread` 返回 `None` | 用 `np.fromfile` + `cv2.imdecode` |
| 默认 BGR | 红蓝互换 | 读入后立刻转 RGB |
| 默认丢掉 alpha | PNG 透明通道没了 | `cv2.IMREAD_UNCHANGED` |

### 8.2 ROI 与坐标

```python
roi = img[y0:y1, x0:x1]      # 先 y 后 x
roi = roi.copy()             # 不想改原图时
```

**坐标约定**（和第 0 篇呼应）：

```
x → 向右（列）
y → 向下（行）
img[y, x]
```

**画图时**：`plt.imshow(img)` 的坐标轴是 `(x, y)`，但数组是 `[y, x]`。在图上标点时，`plt.plot(x, y, 'r.')` 和 `img[y, x]` 指的是同一个像素 —— 这是「图转 90°」bug 的根源。

## 10. 自测

**Q1**：`img.shape == (1080, 1920, 3)`、`dtype == uint8`，一帧多少 MB？30 fps 需要多少带宽？

**Q2**：OpenCV 读进来的图是 BGR，直接送进按 RGB 训练的模型，会发生什么？怎么改？

**Q3**：为什么灰度化不能用 `img.mean(axis=2)`？举一个数值例子。

**Q4**：把 8 bit 压到 4 bit，PSNR 大约多少？为什么是「大约」？

**Q5**：判断对错并说明原因：「缩小图像时直接 `img[::2, ::2]` 和 `cv2.resize` 效果一样。」

**Q6**（换场景）：深度图（每个像素是 mm）应该用什么 dtype 存？为什么不能用 `uint8`？

### 答案

**A1**：`1080×1920×3 = 6,220,800` 字节 ≈ 5.93 MB；30 fps ≈ 178 MB/s。这也是为什么需要 GigE/USB3 和 GPU。

**A2**：红蓝通道互换，颜色特征全错，精度下降；如果模型对颜色敏感（比如按颜色分类），可能直接失效。读入后 `rgb = bgr[..., ::-1]`，并统一项目内的通道约定。

**A3**：平均把三个通道等权，但人眼对绿最敏感。纯绿 (0,255,0)：加权 149.7，平均 85.0；纯蓝 (0,0,255)：加权 29.1，平均 85.0。平均会把「亮绿」和「亮蓝」判成一样亮。

**A4**：约 20 dB（实测 20.28 dB）。「大约」是因为 PSNR 依赖图像内容：平坦图误差小、纹理图误差大；而且均匀量化假设值在各级之间均匀分布，真实图像不一定。

**A5**：错。`img[::2, ::2]` 是点采样，不满足奈奎斯特时会产生混叠（细条纹变粗、亮度偏移）；`cv2.resize(..., INTER_AREA)` 先做面积平均（低通），再采样，不会凭空造出假频率。

**A6**：用 `float32` 或 `uint16`（如果精度够）。`uint8` 只有 256 级，1 m 量程下每级约 4 mm，完全不够；而且深度图还有无效值（0 或 NaN），需要额外标记。

## 11. 坑清单

| # | 坑 | 症状 | 处理 |
|---|---|---|---|
| 1 | 把 BGR 当 RGB | 红蓝互换 | 读入即转，统一约定 |
| 2 | 三通道平均做灰度 | 绿色不够亮、蓝色过亮 | 用 0.299/0.587/0.114 |
| 3 | `uint8` 存 12 bit | 高 4 位被截断，图全白 | 用 `uint16` + 线性映射 |
| 4 | 直接 `astype(uint8)` | 负值绕回、>255 截断 | 先 `clip` |
| 5 | `imread` 返回 `None` | 后面 `img.shape` 报 `AttributeError` | 读后立刻判空 |
| 6 | 缩小时隔点取样 | 摩尔纹、细线消失 | `INTER_AREA` 或先高斯 |
| 7 | `img[x, y]` | 点画到对角线 | 先 y 后 x |
| 8 | 忘记 `strides` 不连续 | 某些算子变慢 | `np.ascontiguousarray` |
