### 0.2 名词卡片

**虚拟环境（virtual environment，venv）**
- 一句话：一个项目一个独立的 Python 包目录，互不污染。
- 不是：不是虚拟机，也不隔离 Python 版本（版本由解释器决定）。
- 用在哪：本篇 §1。

**ndarray（N-dimensional array，N 维数组）**
- 一句话：NumPy 的核心数据结构，一块连续内存 + 形状 + 类型。
- 不是：不是 Python 的 `list`；`list` 存指针，`ndarray` 存值。
- 用在哪：整条 CV 链路，图像、点云、位姿矩阵都是它。

**轴（axis）**
- 一句话：数组的第几个维度；`axis=i` 表示「沿第 i 维变化」。
- 不是：不是「第几列」；对二维数组，`axis=0` 是行方向（结果按列），`axis=1` 是列方向（结果按行）。
- 用在哪：求均值、拼接、归一化。

**dtype（data type，数据类型）**
- 一句话：每个元素占几字节、怎么解释这串比特。
- 常见：`uint8`（0~255，存图）、`float32`（算）、`bool`（掩码）、`int64`（下标）。
- 不是：不是「精度越高越好」；存储用 `uint8`，计算用 `float32`。

**广播（broadcasting）**
- 一句话：形状不同但「能对齐」的数组，自动扩展成同一形状再运算。
- 规则：从最后一维往前比，维度相等或其中一个为 1 就合法。
- 用在哪：逐通道减均值、加偏置、归一化。

**视图 / 拷贝（view / copy）**
- 一句话：视图和原数组共享内存；拷贝是独立副本。
- 判断：`a.base is b` 为 `True` 说明 `a` 是 `b` 的视图。
- 不是：切片**不一定**是视图（花式索引就是拷贝）。

**断言（assertion）**
- 一句话：把「我以为」写成「跑不过就报错」。
- 用在哪：每个 demo 的结尾，锁住关键结论。

**图像坐标 vs 数组下标**
- 图像坐标：`(x, y)`，x 向右、y 向下，单位像素。
- 数组下标：`img[row, col]`，row 向下、col 向右。
- 对应：`row = y`，`col = x`。

## 1. 环境：一个项目一个 venv

### 1.1 为什么不能直接 `pip install`

三个理由，每个都真实发生过：

| 问题 | 后果 |
|---|---|
| 两个项目依赖不同版本 | 升级 A 项目，B 项目跑不起来 |
| 系统 Python 被改坏 | 连 `pip` 本身都可能坏 |
| 没有 `requirements.txt` | 换机器后不知道装了什么版本 |

**venv 解决的是「隔离」，不是「下载」**。包还是从同一个源下载，只是装进项目自己的目录。

### 1.2 建环境（PowerShell，Windows）

在 `codes/` 目录下：

```powershell
cd codes
python -m venv .venv
.venv\Scripts\activate
python -m pip install -U pip
pip install -r requirements.txt
```

`requirements.txt` 只有三行：

```
numpy>=1.24
scipy>=1.10
matplotlib>=3.7
```

**为什么没有 OpenCV**：S0 的目标是「用 NumPy 手写一遍」，装了 `cv2` 反而容易变成调包。等手写跑通，再换 `cv2` 对照，才知道每个参数在干什么。

### 1.3 验证：不要靠「没报错」判断

```powershell
python -c "import numpy, scipy, matplotlib; print(numpy.__version__, scipy.__version__, matplotlib.__version__)"
```

本机实测（Python 3.13.9）：

```
3.13.9
numpy 2.5.4 scipy 1.18.1 mpl 3.11.2
```

三条信息都要对上：**解释器路径、版本号、包能导入**。

### 1.4 三个最常见的环境坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `python` 打开的是 Python 2.7 | 系统里 `python` 指向旧版本 | 用 `py -3`，或直接写 `.venv\Scripts\python.exe` |
| 装完了但 `import` 还是找不到 | 装到了另一个解释器 | `python -m pip install`，保证 pip 和 python 是同一个 |
| 中文路径导致奇怪报错 | 某些工具不认非 ASCII 路径 | 项目放纯英文路径，或确认工具支持 UTF-8 |

> 本仓库的 `codes/.venv` 就是按上面步骤建的。运行脚本时优先用
> `codes\.venv\Scripts\python.exe`，不要依赖全局 `python`。

## 2. ndarray 五个基本功

下面每一段都对应 `00_toolchain.py` 里的一个函数，输出是真实跑出来的。

### 2.1 形状与轴：`axis` 到底压哪一维

```python
img = np.zeros((4, 6, 3), np.uint8)     # H=4, W=6, C=3

img.mean(axis=0).shape   # (6, 3)
img.mean(axis=1).shape   # (4, 3)
img.mean(axis=2).shape   # (4, 6)
```

真实输出：

```
shape        : (4, 6, 3)
mean(axis=0) : (6, 3)  <- 每个 x 位置一条竖线的均值
mean(axis=1) : (4, 3)  <- 每个 y 位置一条横线的均值
mean(axis=2) : (4, 6)  <- 三通道取平均，变成灰度图
```

**记忆法**：`axis=i` 的那一维会消失。想让哪一维消失，就对哪一维做归约。

- 求「整张图一个平均灰度」：`img.mean()`，不写 axis。
- 求「每个通道一个均值」：`img.mean(axis=(0, 1))`，形状 `(3,)`。
- 求「灰度图」：`img.mean(axis=2)`，形状 `(H, W)`。

### 2.2 dtype：`uint8` 会悄悄绕回去

```python
np.uint8(200) + np.uint8(100)   # 300 -> 44
np.uint8(10) - np.uint8(20)     # -10 -> 246
```

真实输出：

```
uint8: 200 + 100 = 44 （期望 300，实际绕回 44）
uint8: 10  - 20  = 246 （期望 -10，实际 246）
float32: 200 + 100 = 300.0
float32: 10  - 20  = -10.0
```

**为什么**：`uint8` 只有 8 位，溢出后按 2⁸ = 256 取模。NumPy 不报错，只给一个 `RuntimeWarning`，很多人把警告过滤掉了，于是拿到一张「亮处变黑」的图。

**三条硬规则**：

1. **存图用 `uint8`**：省内存、省带宽，相机输出通常就是 8 bit。
2. **计算转 `float32`**：减法、除法、加权、梯度，全部先转。
3. **写回前再截断**：`np.clip(x, 0, 255).astype(np.uint8)`，不要直接 `astype`。

**归一化到 `[0,1]` 还是留在 `[0,255]`？**

| 场景 | 建议 | 原因 |
|---|---|---|
| 传统滤波、阈值、形态学 | `[0,255]` 的 `float32` | 阈值直观，和相机参数一致 |
| 深度学习、显示 | `[0,1]` 的 `float32` | 梯度稳定，`imshow` 直接显示 |
| 存盘 | `uint8` | 体积只有 1/4 |

最危险的是「一半 `[0,1]`、一半 `[0,255]`」混用：图会全白或全黑，但不会报错。

### 2.3 广播：不复制内存也能逐通道运算

```python
img = np.random.normal(120, 10, size=(4, 6, 3)).astype(np.float32)
per_channel = img.mean(axis=(0, 1))   # (3,)
balanced = img - per_channel          # (4,6,3) - (3,)
```

真实输出：

```
每通道均值   : [123.93 119.02 120.63]
减去后均值   : [-2.1e-05  1.2e-05  2.0e-06] （应接近 0）
keepdims 形状: (1, 1, 3)
```

**规则**：从最后一维往前比，维度相等或其中一个为 1，就能广播。

```
(4, 6, 3)
      (3,)   -> 最后一维 3 == 3，合法
```

不合法时：

```
(4, 6, 3)
   (6,)      -> 最后一维 3 vs 6，报错
```

**`keepdims=True` 的用处**：让结果保持 `(1,1,3)`，和原图维度数一致，广播时不容易写错轴。

### 2.4 视图 vs 拷贝：切片是窗户，不是复印件

```python
roi = img[1:4, 2:5]     # 视图
roi[:] = 255            # 改视图 = 改原图
```

真实输出：

```
改视图后原图非零像素数: 9 （期望 9）
改副本后原图 (2,3) 的值: 255 （仍是 255）
roi.base is img      : True
roi_copy.base is img : False
```

**什么时候是特性**：

- 在原图上画框、写文字、抠 ROI 做原地处理。
- 大图切片传给函数，避免复制几百 MB。

**什么时候是坑**：

- 把 `roi` 当「备份」存起来，结果原图一改，备份也变了。
- 把切片存进列表，列表里全是同一个视图。

**判断方法**：`a.base is b`；或者改一个像素看另一个变不变。

### 2.5 坐标：`(x, y)` 和 `(row, col)` 是反的

```python
x, y = 30, 70
img[y, x] = 255        # 正确
img[x, y] = 255        # 错误：落到 (x=70, y=30)
```

真实输出：

```
写入 (x=30, y=70) -> 下标 (row=70, col=30)
nonzero 返回 (ys, xs): [70] [30]
若写成 img[x, y] 实际落在 (x=70, y=30)
```

**三条对应关系**：

```
row = y        （行号 = 纵坐标）
col = x        （列号 = 横坐标）
img[y, x]      （先 y 后 x）
```

**为什么容易错**：

- 数学课里点写成 `(x, y)`，先横后纵。
- 数组下标写成 `img[i, j]`，先横（行）后纵（列）。
- 画图函数 `plt.plot(x, y)` 又是先横后纵。

于是「图像转置」「点画到对角线」这类 bug 反复出现。**看到 `img[` 就默念：先 y 后 x。**

`np.nonzero` 返回的顺序也是 `(ys, xs)`，不是 `(xs, ys)` —— 这一点在写质心、轮廓、匹配时天天用到。

## 3. assert：把结论锁死

```python
x = 0.1 + 0.2
x == 0.3            # False
np.isclose(x, 0.3)  # True
```

真实输出：

```
0.1 + 0.2 = 0.30000000000000004  等于 0.3 吗: False
浮点比较：直接 == 不可靠，用 np.allclose
```

**写法**：

```python
assert np.allclose(a, b, atol=1e-6), "a 和 b 应该相等"
```

- `atol`：绝对误差，适合「值接近 0」。
- `rtol`：相对误差，适合「值很大」。
- 两者可以同时给。

**为什么学习阶段必须写 assert**：

- `print` 只能证明「跑到了」，`assert` 才能证明「结果对」。
- 以后改代码，断言会第一时间告诉你哪条结论被破坏了。
- 面试时能说出「我用断言验证了往返误差 < 1e-10」，比「我跑通了」有说服力。

## 4. Git：最小闭环

不需要学分支模型，先会这五条：

```powershell
git status                     # 我改了哪些文件
git diff                       # 具体改了什么
git add notes/S0-.../1-图像是什么.md
git commit -m "docs(S0): 新增图像基础"
git log --oneline -5           # 最近 5 次提交
```

**三条约定**：

1. **一次提交只做一件事**：「新增图像基础」和「修复卷积 bug」不要混在一起。
2. **提交信息写「做了什么」**：`docs(S0): ...`、`feat(codes): ...`、`fix(codes): ...`。
3. **提交前先 `git status`**：确认没有把 `.venv/`、`out/*.png`、临时文件带进去。

本仓库的 `.gitignore` 已经忽略虚拟环境和缓存；图片是否提交按需要决定（本仓库把 `out/` 下的示例图提交了，方便 README 预览）。

## 6. 自测

先遮住答案，再对照。

**Q1**：`img.shape == (480, 640, 3)`，`img.mean(axis=0).shape` 是多少？它代表什么？

**Q2**：为什么 `np.uint8(200) + np.uint8(100)` 等于 44？该怎么算才对？

**Q3**：`roi = img[10:20, 10:20]; roi[:] = 0`，原图会变吗？如果不想变，怎么写？

**Q4**：图像坐标 `(x=100, y=50)` 对应的数组下标是什么？

**Q5**：判断对错并说明原因：「浮点图像精度高，所以图像一律用 `float32` 存。」

**Q6**（换场景）：两帧视频相减做运动检测，为什么必须先 `astype(np.float32)`？

### 答案

**A1**：`(640, 3)`。`axis=0` 沿行方向压缩，剩下「每一列（每个 x）的三个通道均值」。

**A2**：`uint8` 是 8 位无符号整数，只能表示 0~255；300 溢出后按 256 取模，`300 - 256 = 44`。正确做法是先转 `float32`（或 `int16`）再相加。

**A3**：会变。切片是视图，`roi[:] = 0` 直接改共享内存。不想变就 `roi = img[10:20, 10:20].copy()`。

**A4**：`img[50, 100]`，即 `row=50, col=100`。记住 `row=y, col=x`。

**A5**：错。存储用 `uint8` 更省内存和带宽（4K 一帧 5.9 MB，30 fps 约 178 MB/s）；`float32` 只在计算时用。全程 `float32` 会让内存和带宽变成 4 倍。

**A6**：`uint8` 相减会下溢绕回（10 − 20 = 246），暗处变化会被当成「变亮」。转 `float32` 后才能得到负数，再取绝对值或平方。

## 7. 坑清单

| # | 坑 | 症状 | 处理 |
|---|---|---|---|
| 1 | 用全局 `python` 装包 | 装完仍 `ImportError` | `python -m pip`，并用 `sys.executable` 确认 |
| 2 | `axis` 写反 | 得到 `(W,3)` 而不是灰度图 | 记住「axis=i 那一维消失」 |
| 3 | `uint8` 直接相减 | 亮处变黑、出现 246 | 先 `astype(np.float32)` |
| 4 | 忘记 `clip` 就 `astype(uint8)` | 负值绕回、>255 截断 | `np.clip(x,0,255)` 再转 |
| 5 | 把视图当备份 | 改一处，两处都变 | `.copy()` 或 `base is` 检查 |
| 6 | `img[x, y]` | 点画到对角线 | 先 y 后 x |
| 7 | 浮点用 `==` | 偶尔相等、偶尔不等 | `np.allclose` + 容差 |
| 8 | 把 `.venv/` 提交进 Git | 仓库暴涨 | `.gitignore` |
