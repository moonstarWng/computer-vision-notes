## 0. 开始之前：任务与名词

### 0.1 任务：一张「灰蒙蒙」的图，怎么救

场景：背光工位拍到的零件，肉眼看得到划痕，但图像灰度全挤在 100~140，直接阈值什么都分不出来。

**痛点**：

- 调曝光要停机，产线不允许。
- 手调阈值，换一个工位就失效。
- 全局拉对比度，噪声也跟着放大。

**本篇解决哪一步**：先判断「是曝光问题还是对比度问题」，再选工具：线性拉伸、直方图均衡、CLAHE、伽马、还是自适应阈值。

### 0.2 名词卡片

**直方图（histogram）**
- 一句话：每个灰度值有多少个像素。
- 归一化后就是灰度的经验概率分布 `p(k)`。
- 不是：不是「图像的轮廓」；它丢掉了所有空间信息。

**熵（entropy）**
- 一句话：`H = −Σ p(k)·log₂p(k)`，单位 bit，衡量「灰度有多少种可能性」。
- 范围：全同色 `0` bit，256 级均匀 `8` bit；`2^H` 可读作「有效灰度级数」。
- 不是：不是对比度指标。纯噪声熵接近 `8` bit 却毫无用处（§8 有反例）。

**累积分布函数（Cumulative Distribution Function，CDF）**
- 一句话：`CDF(k) = Σ_{i≤k} p(i)`，灰度 ≤ k 的像素占比。
- 用在哪：直方图均衡化的映射表。

**直方图均衡化（histogram equalization）**
- 一句话：用 CDF 当 LUT，把灰度「摊平」。
- 目标：输出 CDF 接近直线（灰度分布均匀）。
- 代价：全局操作，会放大平坦区的噪声。

**限制对比度的自适应直方图均衡（Contrast Limited Adaptive Histogram Equalization，CLAHE）**
- 一句话：分块均衡 + 限幅 + 双线性插值。
- 解决：全局均衡放大噪声、局部细节提不起来。
- 不是：不是「更强的均衡」；它主动**限制**对比度增益。

**伽马校正（gamma correction）**
- 一句话：`out = 255·(in/255)^γ` 的非线性点运算。
- `γ<1` 提亮暗部，`γ>1` 压暗暗部。
- 用在哪：显示、相机、数据增强。

**阈值（threshold）**
- 一句话：`out = 255 if in > t else 0`。
- 全局阈值：一个 `t` 管全图；局部阈值：每个邻域一个 `t`。

**大津法（Otsu's method）**
- 一句话：选让「类间方差」最大的阈值。
- 假设：两类 + 噪声接近高斯 + 光照均匀。
- 失效：光照不均、两类面积悬殊、多峰。

**类间方差 / 可分性（between-class variance / separability）**
- 一句话：`σ_B² = ω0·ω1·(μ0−μ1)²`；`η = σ_B²/σ_total²`。
- `η` 越接近 1，两类分得越开。

## 1. 直方图：先看分布，再动手

### 1.1 怎么算

```python
hist = np.bincount(img.ravel(), minlength=256)   # 每个灰度值的像素数
p = hist / img.size                              # 归一化 = 概率
```

**读图的四个信号**：

| 形状 | 说明 | 该做什么 |
|---|---|---|
| 窄峰（集中在一小段） | 对比度低 | 拉伸 / 均衡 |
| 双峰（两个山包） | 前景背景分离好 | Otsu 阈值 |
| 两端堆积（0 和 255 都有尖峰） | 过曝 + 欠曝 | 调曝光，无法用软件救 |
| 单峰偏左/偏右 | 整体偏暗/偏亮 | 伽马校正 |

### 1.2 本篇的例子

真实输出（低对比度图）：

```
灰度非零区间: [92, 146]，共 55 级
最大 bin 占比: 5.4%
```

256 级里只用了 55 级，且最大的一档占 5.4% —— 典型的「窄峰」。这就是为什么直接阈值分不开：有用的灰度只差几个数，噪声就能把它淹没。

## 2. 点运算 vs 邻域运算

| 类型 | 输出像素依赖 | 例子 |
|---|---|---|
| 点运算 | 只依赖同一位置的输入 | 灰度变换、伽马、阈值 |
| 邻域运算 | 依赖周围一圈 | 卷积、滤波、形态学 |

**点运算的好处**：

- 可以预先算一张 **LUT（Look-Up Table，查找表）**，然后 `out = lut[img]`，复杂度 `O(N)`。
- 不改变几何，不会引入模糊。

**直方图均衡、伽马、阈值都是点运算**，区别只在 LUT 怎么来。

## 3. 线性拉伸：最简单，但要知道边界

```
out = (in − min) · 255 / (max − min)
```

- `min/max`：图里的最小/最大灰度（或 1%/99% 分位数）
- 作用：把 `[min, max]` 线性拉到 `[0, 255]`

**优点**：不改变灰度顺序，不放大噪声比例。
**缺点**：对离群点敏感 —— 一个过曝白点会让 `max=255`，拉伸失效。

**稳健版**：用 1% 和 99% 分位数，而不是绝对最小/最大。

```python
lo, hi = np.percentile(img, [1, 99])
out = np.clip((img - lo) * 255 / (hi - lo), 0, 255)
```

## 4. 直方图均衡化：用 CDF 当映射表

### 4.1 公式

```
s = round( (L−1) · CDF(r) )
CDF(r) = Σ_{k=0}^{r} p(k)
```

- `r`：输入灰度（0~255）
- `s`：输出灰度（0~255）
- `L = 256`：灰度级数
- `p(k)`：灰度 k 的概率
- `CDF`：累积分布，单调不减，范围 `[0,1]`

### 4.2 为什么能把灰度「拉开」

设输入灰度集中在 `[100, 140]`，`p(k)` 在中间很大。则：

- 在 `k=100` 之前，CDF 几乎为 0 → 映射后还是 0。
- 在 `[100,140]` 内，CDF 快速上升 → 映射后跨度很大。
- 在 `k>140` 之后，CDF 接近 1 → 映射后是 255。

**直观**：原来「挤在一起」的地方，CDF 上升快，映射后间隔大；原来「没人」的灰度区间，被直接跳过。

### 4.3 真实数字

```
输入：范围 [92, 146]，均值 114.0，标准差 11.32，熵 5.26 bit，不同灰度 55 级
输出：范围 [0, 255]，均值 131.5，标准差 72.57，熵 5.24 bit，不同灰度 48 级
映射表抽样：
  输入   0 -> 输出   0
  输入 100 -> 输出  18
  输入 110 -> 输出 128
  输入 120 -> 输出 184
  输入 130 -> 输出 223
  输入 140 -> 输出 254
  输入 255 -> 输出 255
输出 CDF 与直线的最大偏差 = 0.049
```

**三个观察**：

1. 标准差从 `11.32` 涨到 `72.57`，对比度确实上去了。
2. 输出 CDF 和直线的最大偏差只有 `0.049`，说明分布接近均匀。
3. **熵反而从 5.26 降到 5.24，不同灰度从 55 级降到 48 级**。

第 3 点很反直觉，但它是必然的：

```
均衡化是单调映射，多个输入灰度可能映射到同一个输出灰度（量化合并）。
合并会减少「不同取值的个数」，所以离散熵不一定上升。
```

所以「均衡化 = 提高熵」是错的。它保证的是 **动态范围铺开**，不是信息量增加。

> 熵既然不跟着「对比度」走，那它到底能说明什么、什么时候该用、什么时候会骗人？§8 专门讲这个。

### 4.4 单调性

```
r1 < r2  ⇒  CDF(r1) ≤ CDF(r2)  ⇒  s1 ≤ s2
```

所以均衡化**不会**把亮的变暗、暗的变亮，只是重新分配间隔。

## 5. 均衡化的问题与 CLAHE

### 5.1 全局均衡的代价

真实输出（9×9 窗口局部标准差的均值）：

```
           全图   平坦背景   零件区
  原图      2.94     2.68     3.61
  全局均衡 21.20    22.97    16.37
  CLAHE     6.73     6.34     7.71
结论：全局均衡把背景噪声放大了 8.6 倍；CLAHE 只放大 2.4 倍，
      但零件区仍然保留细节。
```

**为什么**：全局均衡只看整张图的分布。背景占了大部分像素，CDF 在背景灰度处上升最快，于是背景的微小噪声被映射到很大的输出范围。平坦区本来没有细节，放大后全是噪声。

### 5.2 CLAHE 的三个动作

```
1. 分块（tile）    : 把图切成 8×8 块，每块单独均衡
2. 限幅（clip）    : 直方图超过 clip×平均高度的部分削掉，
                     削掉的总量平均分回每个 bin
3. 插值（bilinear）: 块与块之间双线性混合，消除方块接缝
```

**为什么限幅能压噪声**：噪声让某个 bin 特别高，均衡时这一档被拉得特别开。限幅把「特别高」削平，增益就被限制了。

**参数经验**：

| 参数 | 常用值 | 影响 |
|---|---|---|
| `tiles` | 8×8 | 块越小，局部越强，越容易出块状 |
| `clip` | 2.0~4.0 | 越小越保守，噪声越少 |
| 插值 | 双线性 | 必须开，否则有接缝 |

OpenCV 里一行：

```python
clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8, 8))
out = clahe.apply(gray)
```

**注意**：CLAHE 会改变绝对灰度，做「固定阈值」前要重新标定阈值；做深度学习时，训练和推理要用同一套预处理。

## 6. 伽马校正：非线性点运算

### 6.1 公式与曲线

```
out = 255 · (in / 255)^γ
```

真实输出：

```
gamma | 均值 | 标准差
------|------|-------
 0.45 | 176.8 |   7.79
 1.00 | 114.0 |  11.32
 2.20 |  43.4 |   9.85
```

**怎么读**：

- `γ=0.45`：暗部被大幅提亮，均值 114 → 176.8。
- `γ=2.2`：暗部被压暗，均值 114 → 43.4。
- 标准差反而下降，因为伽马是「压缩」而非「拉伸」：它把暗部拉开、亮部压缩。

### 6.2 为什么需要伽马

两个原因叠加：

1. **人眼**：对暗部的分辨力更强，近似对数响应。
2. **显示器**：电光响应近似 `V^2.2`（CRT 遗留，LCD 也模拟）。

所以图像在存储时要先做 `^(1/2.2)` 的编码（sRGB），显示时再 `^2.2` 解码，人眼看到的才是线性的。

**工程含义**：

- 相机输出的 JPEG/PNG 通常已经过 sRGB 编码，不要再套一次伽马。
- 做光度计算（如结构光、光度立体）时，要先用 `^2.2` 转回线性光强。
- 数据增强里的「亮度扰动」常用伽马，而不是加常数，因为更接近真实光照变化。

## 7. 阈值：从手调到 Otsu

### 7.1 固定阈值

```python
binary = img > 128
```

**问题**：换一个工位、换一批灯，128 就不对了。

### 7.2 Otsu 的推导

把直方图按阈值 `t` 切成两类：

```
背景：灰度 ≤ t，占比 ω0(t)，均值 μ0(t)
前景：灰度 >  t，占比 ω1(t)，均值 μ1(t)
```

类间方差：

```
σ_B²(t) = ω0·ω1·(μ0 − μ1)²
```

代入 `ω0+ω1=1`，可写成只依赖累积量的形式：

```
σ_B²(t) = (μ_t·ω0(t) − μ(t))² / (ω0(t)·(1−ω0(t)))
```

- `ω0(t) = Σ_{k≤t} p(k)`：累积概率
- `μ(t)  = Σ_{k≤t} k·p(k)`：累积一阶矩
- `μ_t`：全图均值

**选让 `σ_B²` 最大的 `t`**，就是 Otsu 阈值。

**可分性**：

```
η = σ_B²(t*) / σ_total²
```

`η` 越接近 1，说明「两类之间的差异」占「总差异」的比例越大，分得越开。

### 7.3 真实数字

```
真实阈值在 130 附近（80 与 180 的中点）
Otsu 阈值 = 128，类间方差 = 1500.9，可分性 η = 0.913
二值化准确率 = 100.00%
光照不均后：Otsu 阈值 = 94，可分性 η = 0.694，准确率 = 84.39%
（左侧暗、右侧亮，同一个零件在直方图上被摊成两个峰，单阈值救不了）
```

**为什么光照不均会失效**：

```
原始：背景 80，零件 180 → 两个清晰的峰
渐晕后：左边背景 28、零件 63；右边背景 108、零件 243
直方图变成四个峰（或一片糊），一个阈值不可能同时切开左右两边
```

**解法**：

| 方法 | 做法 | 适用 |
|---|---|---|
| 局部阈值 | 每个 `k×k` 邻域算一个 Otsu/均值 | 光照缓慢变化 |
| 自适应阈值 | `cv2.adaptiveThreshold`（均值/高斯） | 文档、表面缺陷 |
| 先做光照校正 | 除以背景估计（大核模糊/同态滤波） | 渐晕、反光 |
| 深度学习 | 直接学「什么算缺陷」 | 复杂纹理 |

### 7.4 阈值后的形态学

阈值出来的二值图一定有噪点和小孔。下一步通常是形态学（第 4 篇），顺序一般是：

```
灰度图 → 滤波（可选）→ 阈值 → 开运算（去噪点）→ 闭运算（填孔）→ 连通域
```

## 8. 熵：能说什么，不能说什么

熵的定义在 §0.2，§4.3 里它已经出现过一次（`5.26 → 5.24`）。这一节只回答两件事：**为什么需要它**、**什么样的熵算「好」**。

### 8.1 一张表就够了

四张 256×256 图，同一个熵函数（脚本「六、熵的适用边界」）：

| 图像 | std | 熵 (bit) | 2^H | 9×9 局部 std |
|---|---|---|---|---|
| 均匀噪声 | 74.05 | **7.989** | 254.1 | 73.48 |
| 高斯灰度 | 39.80 | 7.352 | 163.4 | 39.43 |
| 低对比度零件 | 9.43 | 4.847 | 28.8 | 1.07 |
| 干净二值零件 | 112.11 | **0.830** | 1.8 | 6.87 |

四条结论：

1. **熵最高的图最没用**。均匀噪声 `7.989`，几乎顶到 256 级的上限 8 bit —— 随机 = 完全不可预测 = 熵最大。
2. **熵最低的图最好用**。干净二值零件 `0.830`，只有两个灰度级，边缘能定位到单像素。
3. **熵低 ≠ 对比度低**。同一张图 `std = 112.11`，比噪声的 `74.05` 还高。
4. **两个指标的排序不一致**。按 std 排是「二值 > 噪声 > 高斯 > 低对比」，按熵排是「噪声 > 高斯 > 低对比 > 二值」。选哪个指标，决定你「看见」什么。

一句话：**熵量的是「取值有多少种可能」，不是「图能不能用」。**

### 8.2 那它到底哪里有用

三个层次：

1. **无损压缩的下界**。`H` 就是平均每像素最少需要多少 bit：`5.26 bit × 35200 px ≈ 1.85×10⁵ bit ≈ 23 KB`。任何无损编码都不可能比它更小。std 是灰阶单位，换算不成字节，做不到这件事。
2. **比 std 更完整**。std 只用分布的二阶矩。`0`/`255` 各占一半的图：`std = 127.5`（比噪声还大），`H = 1.000 bit`（只有噪声的 1/8）—— 这就是「跨度」和「取值多样性」的区别。
3. **可以作用在任意分布上**。std 只能对数值算；熵能对灰度、梯度、联合分布、类别概率算。这是它不可替代的地方。

落到 CV，只有三类场景是「熵（或它的派生量）越大越好」：

| 场景 | 判据 | 为什么 |
|---|---|---|
| 多模态配准 | 互信息 `MI = H(A) + H(B) − H(A,B)` 最大 | 可见光/红外/雷达灰度不同，相关系数失效，MI 仍能对齐（M2 的外参标定用的就是它） |
| 最大熵分割（Kapur） | 前景熵 + 背景熵 最大 | 与 Otsu 互补：Otsu 看两类均值离多远，Kapur 看两类内部还剩多少不确定 |
| 主动学习 / 半监督 | 预测熵最大 → 送标注；熵最小化 → 正则项 | 熵在这里是「模型有多犹豫」 |

其余场景里，熵只有两种身份：**下界**（压缩）或**守门员**（预处理有没有把信息压没）。

### 8.3 两个陷阱

**分箱不可比**。`5.26 bit` 是 256 个 bin 下的结果。量化到 64 级再算会变小；按连续分布算微分熵甚至可以是负数。**报熵必须同时报 bin 宽度和位深**，「这张图熵 6.5」单独说是没有意义的。

**看不见结构**。棋盘格和它被打乱后的版本，直方图、std、熵完全相同，但一个可测、一个不可测。要区分只能上局部指标：9×9 局部 std（§5.1 那张表）、梯度幅值、自相关、SSIM。

### 8.4 验收时看什么

| 目的 | 看什么 | 熵的角色 |
|---|---|---|
| 对比度够不够 | 动态范围、std、9×9 局部 std、0/255 饱和比例 | **不用** |
| 预处理有没有丢信息 | 熵不应异常骤降 | 守门员 |
| 多模态配准 | MI 最大 | 越大越好 |
| 阈值分割 | 类间方差（Otsu）/ 两类熵和（Kapur） | 目标函数 |
| 压缩评估 | 实际 bit/px 与 H 的差 = 冗余 | 下界 |

最后一条直觉，顺带解释 PNG 为什么能压到 1~2 bit/px：**有意义的图像，逐像素熵本来就不该接近 8 bit**。自然图相邻像素高度相关，「已知左邻上邻」的条件熵只有 2~3 bit；熵接近 8 恰恰说明它已经是噪声了。

## 10. 自测

**Q1**：直方图两端（0 和 255）都有很高的尖峰，说明什么？软件能救吗？

**Q2**：均衡化后标准差从 11.32 涨到 72.57，为什么熵反而略降？

**Q3**：CLAHE 的「限幅」限的是什么？为什么能压噪声？

**Q4**：`γ=0.45` 和「把图整体加 50」有什么区别？

**Q5**：Otsu 的 `η=0.913` 和 `η=0.694`，哪个分得好？为什么光照不均会让它下降？

**Q6**（换场景）：彩色图能不能直接对 BGR 三个通道分别做均衡化？会有什么问题？

**Q7**：一张纯噪声图的熵是 `7.989` bit（接近 8 bit 上限），能说它「信息丰富」吗？

### 答案

**A1**：同时存在过曝（255 堆积）和欠曝（0 堆积），动态范围不够。软件无法恢复已经截断的高光/阴影，只能改曝光或换 HDR。

**A2**：均衡化是单调映射，多个输入灰度会被合并到同一个输出灰度（量化），不同取值个数从 55 降到 48，离散熵因此略降。它提高的是动态范围，不是信息量（详见 §8）。

**A3**：限的是每个直方图 bin 的高度（`clip × 平均高度`）。噪声让某个 bin 异常高，均衡时会被过度拉伸；削平后增益被限制，噪声不会被放大到极端。

**A4**：加常数是线性平移，会整体变亮并可能截断高光；伽马是非线性，主要提亮暗部、压缩亮部，高光更不容易溢出。

**A5**：`η=0.913` 分得好。光照不均让同一类（背景或零件）的灰度跨越很大范围，类内方差变大、类间方差占比下降，所以 `η` 降低，单阈值失效。

**A6**：可以，但会破坏颜色一致性：三个通道的 CDF 不同，均衡后比例变了，颜色会偏。正确做法是只对亮度通道（HSV 的 V、或 Lab 的 L）做均衡，色度保持不变。

**A7**：不能。熵高只说明「灰度取值接近均匀、难以预测」，随机噪声正好如此，但它没有任何可用信息，也定位不了边缘。熵量的是「有多少种可能」，不是「能不能用」；评价对比度要看动态范围、std、9×9 局部 std（§8.1 的四张图）。

> 以上是「懂没懂」的自查。§11 是同一批内容的**面试口径**——不是再考一遍，而是给你能直接开口讲的稿子。

### 11.1 判读：这张图还能不能用（1 题）

**Q1. 拿到一张「灰蒙蒙」的图，你怎么判断它是曝光问题还是对比度问题？** ★

**一句话**：看直方图两端——两端空是「挤」，两端堆是「截断」。

**讲开**：

- 直方图就是「每个灰度有多少像素」，归一化后是 `p(k)`，一眼能判断这张图值不值得处理。
- **两端空、中间一个窄峰**：信息还在，只是挤在一起，点运算能救（本篇例子只用 `[92,146]`、55 级、最大一档占 5.4%）。
- **0 和 255 都堆尖峰**：已经截断，像素撞到上下限、梯度丢失，软件救不回来，只能改曝光或上 HDR。
- 判完再选工具：窄峰 → 拉伸/均衡；整体偏暗 → 伽马；双峰 → Otsu；光照不均 → 局部阈值。

**数字锚点**：输入 `[92,146]`、55 级、最大 bin 5.4%；均衡后铺满 `[0,255]`、std 11.32 → 72.57。

**追问**：「没有直方图工具怎么办？」→ 看 0/255 的像素占比和局部对比度，量的还是同一个分布。

### 11.2 工具箱与取舍（5 题）

**Q2. 线性拉伸和直方图均衡，什么时候用哪个？** ★

**一句话**：拉伸是「线性缩放跨度」，均衡是「用 CDF 改形状」。

**讲开**：

- 拉伸 `out = (in−min)·255/(max−min)`：线性、保序、只看两个端点，分布形状不变。
- 均衡 `s = round(255·CDF(r))`：非线性，按累积概率重新分配，目标是输出分布接近均匀。
- 只想用满动态范围、要可预测 → **拉伸**；灰度挤在窄峰、要拉开中间 → **均衡/CLAHE**。
- 拉伸怕离群点（一个过曝白点就让 `max=255`），所以工程上用 1%/99% 分位数。

**数字锚点**：拉伸的噪声增益是**一个常数**（`255/(hi−lo)`）；均衡的增益随位置变化，背景处最大（见 Q3 的 8.6 倍）。

**追问**：「为什么拉伸不会像均衡那样放大噪声？」→ 线性映射对全图用同一个比例，没有局部额外增益。

**Q3. 全局均衡和 CLAHE 差在哪？为什么全局均衡会放大噪声？** ★

**一句话**：全局用一个 CDF 管全图，背景占多数，就把背景的噪声放大了。

**讲开**：

- 均衡的增益 `ds/dr = 255·p(r)`——**某个灰度的像素越多，那一档被拉得越开**。
- 背景通常占大半像素，于是背景所在的灰度区间 CDF 最陡、增益最大，平坦区的微小噪声被放大成大颗粒。
- CLAHE 三步补救：分块（8×8）各自均衡 + **限幅**（削掉超过 `clip×平均高度` 的 bin）+ 双线性插值消除接缝。
- 限幅的意义：噪声让某个 bin 异常高，削平它就等于**给增益设上界**。

**数字锚点**：平坦背景的 9×9 局部 std，原图 2.68 → 全局均衡 **22.97**（8.6 倍）→ CLAHE **6.34**（2.4 倍）。

**追问**：「clip 是不是越小越好？」→ 不是，太小等于弱均衡，细节提不起来；2~4 是折中。

**Q4. 伽马校正和「整体加 50 灰度」有什么区别？** ★★

**一句话**：加常数是平移（会截断高光），伽马是压缩（提暗部、压亮部）。

**讲开**：

- 加常数：`out = in + c`，线性平移，暗部**间距不变**，超过 255 的部分直接削平（不可逆）。
- 伽马：`out = 255·(in/255)^γ`，`γ<1` 把暗部拉开、亮部压紧；`γ>1` 相反。
- 所以伽马是「压缩」不是「拉伸」——直方图被挤到一侧，**标准差反而下降**。
- 工程上「提亮」优先用伽马，因为高光不容易溢出，也更接近真实光照变化。

**数字锚点**：`γ=0.45` 均值 114.0 → 176.8、std 11.32 → 7.79；`γ=2.2` 均值 → 43.4。

**追问**：「为什么相机和显示器都要伽马？」→ 人眼近似对数响应 + CRT 的 `V^2.2`，sRGB 存的是编码值不是线性光强。

**Q5. 固定阈值、Otsu、局部阈值，各自在哪失效？** ★★★

**一句话**：固定阈值怕换环境，Otsu 怕光照不均，局部阈值怕噪声和块效应。

**讲开**：

- **固定阈值**：阈值是外部常量，换工位、换灯、换批次就废——它没有用到图像自己的分布。
- **Otsu**：最大化类间方差 `σ_B² = ω0·ω1·(μ0−μ1)²`，前提是**双峰 + 类内近似高斯 + 光照均匀**。光照不均时同一类被摊成多峰，`σ_B²` 下降。
- **局部/自适应阈值**：假设光照在邻域内近似均匀，能救缓变光照；代价是块效应、平坦区放大噪声、参数变多。
- 现场判断靠 `η = σ_B²/σ_total²`（可分性）：`η` 高才敢用单阈值。

**数字锚点**：干净双峰 `t=128、η=0.913、准确率 100%`；加渐晕后 `t=94、η=0.694、准确率 84.39%`。

**追问**：「`η` 掉到多少就该换方法？」→ 没有硬阈值，但 `η<0.7` 时单阈值基本不可信，先做光照校正或换局部法。

**Q6. 手算：灰度集中在 `[100,140]` 的图，均衡化后输入 110 会映射到哪？** ★

**一句话**：`s = round(255·CDF(110))`，即「灰度 ≤110 的像素占比 × 255」。

**讲开**：

- 四步：数直方图 → 除以像素总数得 `p(k)` → 累加得 `CDF(110)` → 乘 255 取整。
- 实测这张图的 LUT 里 **110 → 128**，反推 `CDF(110) ≈ 128/255 ≈ 0.502`——刚好一半像素在 110 以下。
- 同一张 LUT 抽样：`100→18`、`130→223`、`140→254`，可见中间被拉得很开、两端被压扁。
- 这就是「均衡化把常出现的灰度区间放大」的量化证据。

**数字锚点**：`110 → 128`，`CDF(110) ≈ 0.502`；输出 CDF 与直线最大偏差只有 0.049。

**追问**：「为什么不直接用 min/max 拉伸？」→ CDF 按分布分配，能把窄峰摊平；min/max 只看两个端点，跟分布形状无关。

### 11.3 翻车点：现场最常被追问的地方（5 题）

**Q7. 直方图两端（0 和 255）都有很高的尖峰，说明什么？软件能救吗？** ★

**一句话**：同时过曝和欠曝，动态范围不够；**截断的部分不可逆**。

**讲开**：

- 0 堆 = 暗部被压到下限，255 堆 = 亮部被顶到上限，两头的像素值全一样，**梯度信息已经丢了**。
- 这不是「对比度低」，是「信息缺失」——任何点运算都只能把 0 抬起来，抬起来的还是 0。
- 真解：改曝光/光圈、补光、偏振片压反光、多曝光 HDR 合成。
- 只有一个端点堆：0 堆是欠曝（提亮时噪声一起提），255 堆是过曝（最不可救）。

**数字锚点**：本篇低对比度图只在 `[92,146]` 内，**0 和 255 的像素占比为 0**——这才是「能救」的前提。

**追问**：「那为什么说饱和像素最危险？」→ 它让同一块区域的所有像素相等，边缘、纹理、亚像素信息全部归零。

**Q8. 彩色图能不能对 BGR 三个通道分别做均衡？会有什么问题？** ★★

**一句话**：能算，但会偏色——三个通道的 CDF 不同，拉伸比例就不同。

**讲开**：

- 每个通道独立做均衡 → 各自的映射曲线不同 → R/G/B 的相对比例被改变 → **白平衡被破坏**，颜色飘。
- 正确做法：只处理**亮度**，色度不动——HSV 的 `V`、Lab 的 `L`、YCrCb 的 `Y`。
- 单通道场景（灰度相机、工业黑白图）没有这个问题，随便做。
- 反例：水下/雾天那种「颜色本身需要校正」的任务，用的是颜色恒常/白平衡算法，不是逐通道 CDF。

**数字锚点**：实测把一块中性灰 `(120,120,120)` 逐通道均衡，输出变成 `(214,255,255)`——R/G/B 极差 41，肉眼就是一块青色。因为这三个通道在灰度 120 处的 CDF 分别是 0.84 / 1.00 / 1.00，同一个输入被三条不同曲线拉走了。

**追问**：「那先转灰度再均衡，最后还原彩色行不行？」→ 不行，颜色信息已经丢了；要保留彩色就必须动亮度通道、不动色度。

**Q9. 均衡化或 CLAHE 之后，还能用原来的固定阈值吗？** ★★

**一句话**：不能，LUT 变了，同一个灰度值的含义就变了。

**讲开**：

- 均衡/CLAHE 是**点运算**：`out = lut[in]`，输入 110 变成 128，原来标定的 `t=128` 现在切在完全不同的物理位置。
- 后果：原本能分开的前景背景，可能一刀切错，误检率飙升。
- 三个解法：重新标定阈值 / 直接在同一域里用 Otsu / 把预处理固化进流水线（训练和推理必须同一套）。
- 这条对深度学习同样成立：训练用 CLAHE、推理忘了做，就是分布漂移。

**数字锚点**：同一张 LUT 抽样 `100→18`、`110→128`、`130→223`——映射非线性，所以阈值不能平移过去用。

**追问**：「为什么 CLAHE 比全局均衡更容易踩这个坑？」→ 它是分块 + 插值的，每个位置的映射都不同，一个全局阈值更没意义。

**Q10. 相机直接出的 JPEG，为什么不宜再套一次伽马？** ★★

**一句话**：JPEG 已经按 sRGB 编码过一次，再套一次是「二次编码」。

**讲开**：

- 相机/显示器链路里，存储时做了约 `^(1/2.2)` 的编码、显示时用 `^2.2` 解码，人眼才看到线性亮度。
- 你直接对 sRGB 值再乘一条伽马曲线，等于把两条曲线**叠乘**：暗部被过度提亮，中间调塌陷，对比度变怪。
- 做光度类计算（结构光、光度立体、颜色测量、模板匹配）必须先用 `^2.2` 转回**线性光强**，算完再编码回去。
- 数据增强里的「亮度扰动」用伽马是对的——但那是故意改变外观，不是做测量。

**数字锚点**：sRGB 存的是 `L^(1/2.2)`，再套一条 `γ=0.45`，等效指数是 `0.45/2.2 ≈ 0.20`——暗部被提亮到夸张，中间调塌陷。

**追问**：「怎么确认手上的图有没有被编码过？」→ 看格式（JPEG/PNG 基本是 sRGB）和来源（RAW/线性 TIFF 才是线性的），或者用灰卡测响应曲线。

**Q11. 光照不均时 Otsu 为什么失效？现场怎么救？** ★★

**一句话**：同一类物体的灰度被光照摊开，双峰糊掉，一个阈值切不开两类。

**讲开**：

- 渐晕/侧光让「同一类」在不同位置灰度差很大（左边背景 28、右边背景 108），直方图上变成多峰或一片糊。
- Otsu 只找**一个** `t`，它无法同时满足左右两边——`σ_B²` 上不去，`η` 掉下来。
- 救法按成本排序：局部阈值（滑动窗口 Otsu/均值）→ `cv2.adaptiveThreshold` → 先做光照校正（除背景估计/同态滤波）→ 深度学习。
- 判断该不该救：先算 `η`，再看「同一零件左右两侧的灰度差」有多大。

**数字锚点**：`η` 0.913 → 0.694，准确率 100% → 84.39%。

**追问**：「先做全局均衡再 Otsu 行不行？」→ 不行，均衡是全局单调映射，改不了「同一类跨多个灰度」这件事，还会顺带放大噪声。

### 11.4 验收：用什么指标，别用错（1 题）

**Q12. 标准差和熵都在描述分布，差别是什么？验收该看哪个？** ★★★

**一句话**：std 量「跨度」，熵量「有多少种取值」；验收对比度看 std，不看熵。

**讲开**：

- `std` 只用二阶矩（一个数），`H=−Σp·log₂p` 用整个分布，所以两者排序可以完全不同。
- 两个反例：`0/255` 各占一半 → std **127.5**（最大）但 `H=1.0`；均匀噪声 → std 74.05 但 `H=7.989`（接近上限 8）。
- 所以「熵高 = 图好」是错的：噪声熵最高却最没用，干净二值零件熵最低（0.830）却最可测。
- 熵的正经用途只有三处：压缩下界、互信息配准、最大熵/Kapur 分割；验收对比度用动态范围 + std + 9×9 局部 std。

**数字锚点**：均衡化 std 11.32 → 72.57，熵 5.26 → 5.24（因为量化把 55 级压到 48 级）。

**追问**：「那为什么教材里总说均衡化最大化熵？」→ 那是**连续**分布的结论；离散 + `round` 量化后会打折扣，甚至下降。

| 1 | 以为均衡化一定提高熵 | 指标对不上 | 看动态范围/标准差，不看熵（§8.1） |
| 2 | 对彩色图逐通道均衡 | 颜色偏色 | 只对亮度通道做 |
| 3 | 均衡后再用固定阈值 | 阈值全变 | 重新标定，或改用 Otsu |
| 4 | CLAHE 的 tile 太小 | 块状伪影 | tile ≥ 8×8，开插值 |
| 5 | 相机 JPEG 上再做伽马 | 二次编码，对比度怪 | 确认是否已 sRGB |
| 6 | Otsu 用在光照不均 | 准确率骤降 | 局部阈值 / 光照校正 |
| 7 | 用最小/最大做拉伸 | 一个白点毁全图 | 用 1%/99% 分位数 |
| 8 | 阈值后不做形态学 | 噪点、孔洞多 | 开/闭运算 + 面积过滤 |
| 9 | 跨位深/跨分箱比较熵 | 数字对不上 | 熵必须和 bin 宽度、位深一起报（§8.3） |
| 10 | 用熵当「图变好了」的验收指标 | 噪声图得分最高 | 用动态范围 / std / 局部 std（§8.4） |
