## 0. 开始之前：任务与名词

### 0.1 任务：一张「灰蒙蒙」的图，怎么救

场景：背光工位拍到的零件，肉眼看得到划痕，但图像灰度全挤在 100~140，直接阈值什么都分不出来。

**痛点**：

- 调曝光要停机，产线不允许。
- 手调阈值，换一个工位就失效。
- 全局拉对比度，噪声也跟着放大。

**本篇解决哪一步**：先判断「是曝光问题还是对比度问题」，再选工具：线性拉伸、直方图均衡、CLAHE、伽马、还是自适应阈值。

### 0.2 名词卡片

**直方图（histogram）**
- 一句话：每个灰度值有多少个像素。
- 归一化后就是灰度的经验概率分布 `p(k)`。
- 不是：不是「图像的轮廓」；它丢掉了所有空间信息。

**累积分布函数（Cumulative Distribution Function，CDF）**
- 一句话：`CDF(k) = Σ_{i≤k} p(i)`，灰度 ≤ k 的像素占比。
- 用在哪：直方图均衡化的映射表。

**直方图均衡化（histogram equalization）**
- 一句话：用 CDF 当 LUT，把灰度「摊平」。
- 目标：输出 CDF 接近直线（灰度分布均匀）。
- 代价：全局操作，会放大平坦区的噪声。

**限制对比度的自适应直方图均衡（Contrast Limited Adaptive Histogram Equalization，CLAHE）**
- 一句话：分块均衡 + 限幅 + 双线性插值。
- 解决：全局均衡放大噪声、局部细节提不起来。
- 不是：不是「更强的均衡」；它主动**限制**对比度增益。

**伽马校正（gamma correction）**
- 一句话：`out = 255·(in/255)^γ` 的非线性点运算。
- `γ<1` 提亮暗部，`γ>1` 压暗暗部。
- 用在哪：显示、相机、数据增强。

**阈值（threshold）**
- 一句话：`out = 255 if in > t else 0`。
- 全局阈值：一个 `t` 管全图；局部阈值：每个邻域一个 `t`。

**大津法（Otsu's method）**
- 一句话：选让「类间方差」最大的阈值。
- 假设：两类 + 噪声接近高斯 + 光照均匀。
- 失效：光照不均、两类面积悬殊、多峰。

**类间方差 / 可分性（between-class variance / separability）**
- 一句话：`σ_B² = ω0·ω1·(μ0−μ1)²`；`η = σ_B²/σ_total²`。
- `η` 越接近 1，两类分得越开。

## 1. 直方图：先看分布，再动手

### 1.1 怎么算

```python
hist = np.bincount(img.ravel(), minlength=256)   # 每个灰度值的像素数
p = hist / img.size                              # 归一化 = 概率
```

**读图的四个信号**：

| 形状 | 说明 | 该做什么 |
|---|---|---|
| 窄峰（集中在一小段） | 对比度低 | 拉伸 / 均衡 |
| 双峰（两个山包） | 前景背景分离好 | Otsu 阈值 |
| 两端堆积（0 和 255 都有尖峰） | 过曝 + 欠曝 | 调曝光，无法用软件救 |
| 单峰偏左/偏右 | 整体偏暗/偏亮 | 伽马校正 |

### 1.2 本篇的例子

真实输出（低对比度图）：

```
灰度非零区间: [92, 146]，共 55 级
最大 bin 占比: 5.4%
```

256 级里只用了 55 级，且最大的一档占 5.4% —— 典型的「窄峰」。这就是为什么直接阈值分不开：有用的灰度只差几个数，噪声就能把它淹没。

## 2. 点运算 vs 邻域运算

| 类型 | 输出像素依赖 | 例子 |
|---|---|---|
| 点运算 | 只依赖同一位置的输入 | 灰度变换、伽马、阈值 |
| 邻域运算 | 依赖周围一圈 | 卷积、滤波、形态学 |

**点运算的好处**：

- 可以预先算一张 **LUT（Look-Up Table，查找表）**，然后 `out = lut[img]`，复杂度 `O(N)`。
- 不改变几何，不会引入模糊。

**直方图均衡、伽马、阈值都是点运算**，区别只在 LUT 怎么来。

---

## 3. 线性拉伸：最简单，但要知道边界

```
out = (in − min) · 255 / (max − min)
```

- `min/max`：图里的最小/最大灰度（或 1%/99% 分位数）
- 作用：把 `[min, max]` 线性拉到 `[0, 255]`

**优点**：不改变灰度顺序，不放大噪声比例。
**缺点**：对离群点敏感 —— 一个过曝白点会让 `max=255`，拉伸失效。

**稳健版**：用 1% 和 99% 分位数，而不是绝对最小/最大。

```python
lo, hi = np.percentile(img, [1, 99])
out = np.clip((img - lo) * 255 / (hi - lo), 0, 255)
```

## 4. 直方图均衡化：用 CDF 当映射表

### 4.1 公式

```
s = round( (L−1) · CDF(r) )
CDF(r) = Σ_{k=0}^{r} p(k)
```

- `r`：输入灰度（0~255）
- `s`：输出灰度（0~255）
- `L = 256`：灰度级数
- `p(k)`：灰度 k 的概率
- `CDF`：累积分布，单调不减，范围 `[0,1]`

### 4.2 为什么能把灰度「拉开」

设输入灰度集中在 `[100, 140]`，`p(k)` 在中间很大。则：

- 在 `k=100` 之前，CDF 几乎为 0 → 映射后还是 0。
- 在 `[100,140]` 内，CDF 快速上升 → 映射后跨度很大。
- 在 `k>140` 之后，CDF 接近 1 → 映射后是 255。

**直观**：原来「挤在一起」的地方，CDF 上升快，映射后间隔大；原来「没人」的灰度区间，被直接跳过。

### 4.3 真实数字

```
输入：范围 [92, 145]，均值 114.0，标准差 11.32，熵 5.26 bit，不同灰度 54 级
输出：范围 [0, 255]，均值 131.4，标准差 72.58，熵 5.24 bit，不同灰度 48 级
映射表抽样：
  输入   0 -> 输出   0
  输入 100 -> 输出  18
  输入 110 -> 输出 128
  输入 120 -> 输出 184
  输入 130 -> 输出 223
  输入 140 -> 输出 254
  输入 255 -> 输出 255
输出 CDF 与直线的最大偏差 = 0.050
```

**三个观察**：

1. 标准差从 `11.32` 涨到 `72.58`，对比度确实上去了。
2. 输出 CDF 和直线的最大偏差只有 `0.050`，说明分布接近均匀。
3. **熵反而从 5.26 降到 5.24，不同灰度从 54 级降到 48 级**。

第 3 点很反直觉，但它是必然的：

```
均衡化是单调映射，多个输入灰度可能映射到同一个输出灰度（量化合并）。
合并会减少「不同取值的个数」，所以离散熵不一定上升。
```

所以「均衡化 = 提高熵」是错的。它保证的是 **动态范围铺开**，不是信息量增加。

### 4.4 单调性

```
r1 < r2  ⇒  CDF(r1) ≤ CDF(r2)  ⇒  s1 ≤ s2
```

所以均衡化**不会**把亮的变暗、暗的变亮，只是重新分配间隔。

## 5. 均衡化的问题与 CLAHE

### 5.1 全局均衡的代价

真实输出（9×9 窗口局部标准差的均值）：

```
           全图   平坦背景   零件区
  原图      2.93     2.68     3.59
  全局均衡 21.12    22.89    16.20
  CLAHE     6.70     6.32     7.64
结论：全局均衡把背景噪声放大了 8.6 倍；CLAHE 只放大 2.4 倍，
      但零件区仍然保留细节。
```

**为什么**：全局均衡只看整张图的分布。背景占了大部分像素，CDF 在背景灰度处上升最快，于是背景的微小噪声被映射到很大的输出范围。平坦区本来没有细节，放大后全是噪声。

### 5.2 CLAHE 的三个动作

```
1. 分块（tile）    : 把图切成 8×8 块，每块单独均衡
2. 限幅（clip）    : 直方图超过 clip×平均高度的部分削掉，
                     削掉的总量平均分回每个 bin
3. 插值（bilinear）: 块与块之间双线性混合，消除方块接缝
```

**为什么限幅能压噪声**：噪声让某个 bin 特别高，均衡时这一档被拉得特别开。限幅把「特别高」削平，增益就被限制了。

**参数经验**：

| 参数 | 常用值 | 影响 |
|---|---|---|
| `tiles` | 8×8 | 块越小，局部越强，越容易出块状 |
| `clip` | 2.0~4.0 | 越小越保守，噪声越少 |
| 插值 | 双线性 | 必须开，否则有接缝 |

OpenCV 里一行：

```python
clahe = cv2.createCLAHE(clipLimit=2.0, tileGridSize=(8, 8))
out = clahe.apply(gray)
```

**注意**：CLAHE 会改变绝对灰度，做「固定阈值」前要重新标定阈值；做深度学习时，训练和推理要用同一套预处理。

## 6. 伽马校正：非线性点运算

### 6.1 公式与曲线

```
out = 255 · (in / 255)^γ
```

真实输出：

```
gamma | 均值 | 标准差
------|------|-------
 0.45 | 176.8 |   7.79
 1.00 | 114.0 |  11.32
 2.20 |  43.4 |   9.85
```

**怎么读**：

- `γ=0.45`：暗部被大幅提亮，均值 114 → 176.8。
- `γ=2.2`：暗部被压暗，均值 114 → 43.4。
- 标准差反而下降，因为伽马是「压缩」而非「拉伸」：它把暗部拉开、亮部压缩。

### 6.2 为什么需要伽马

两个原因叠加：

1. **人眼**：对暗部的分辨力更强，近似对数响应。
2. **显示器**：电光响应近似 `V^2.2`（CRT 遗留，LCD 也模拟）。

所以图像在存储时要先做 `^(1/2.2)` 的编码（sRGB），显示时再 `^2.2` 解码，人眼看到的才是线性的。

**工程含义**：

- 相机输出的 JPEG/PNG 通常已经过 sRGB 编码，不要再套一次伽马。
- 做光度计算（如结构光、光度立体）时，要先用 `^2.2` 转回线性光强。
- 数据增强里的「亮度扰动」常用伽马，而不是加常数，因为更接近真实光照变化。

## 7. 阈值：从手调到 Otsu

### 7.1 固定阈值

```python
binary = img > 128
```

**问题**：换一个工位、换一批灯，128 就不对了。

### 7.2 Otsu 的推导

把直方图按阈值 `t` 切成两类：

```
背景：灰度 ≤ t，占比 ω0(t)，均值 μ0(t)
前景：灰度 >  t，占比 ω1(t)，均值 μ1(t)
```

类间方差：

```
σ_B²(t) = ω0·ω1·(μ0 − μ1)²
```

代入 `ω0+ω1=1`，可写成只依赖累积量的形式：

```
σ_B²(t) = (μ_t·ω0(t) − μ(t))² / (ω0(t)·(1−ω0(t)))
```

- `ω0(t) = Σ_{k≤t} p(k)`：累积概率
- `μ(t)  = Σ_{k≤t} k·p(k)`：累积一阶矩
- `μ_t`：全图均值

**选让 `σ_B²` 最大的 `t`**，就是 Otsu 阈值。

**可分性**：

```
η = σ_B²(t*) / σ_total²
```

`η` 越接近 1，说明「两类之间的差异」占「总差异」的比例越大，分得越开。

### 7.3 真实数字

```
真实阈值在 130 附近（80 与 180 的中点）
Otsu 阈值 = 129，类间方差 = 1513.8，可分性 η = 0.912
二值化准确率 = 100.00%
光照不均后：Otsu 阈值 = 94，可分性 η = 0.692，准确率 = 84.71%
（左侧暗、右侧亮，同一个零件在直方图上被摊成两个峰，单阈值救不了）
```

**为什么光照不均会失效**：

```
原始：背景 80，零件 180 → 两个清晰的峰
渐晕后：左边背景 28、零件 63；右边背景 108、零件 243
直方图变成四个峰（或一片糊），一个阈值不可能同时切开左右两边
```

**解法**：

| 方法 | 做法 | 适用 |
|---|---|---|
| 局部阈值 | 每个 `k×k` 邻域算一个 Otsu/均值 | 光照缓慢变化 |
| 自适应阈值 | `cv2.adaptiveThreshold`（均值/高斯） | 文档、表面缺陷 |
| 先做光照校正 | 除以背景估计（大核模糊/同态滤波） | 渐晕、反光 |
| 深度学习 | 直接学「什么算缺陷」 | 复杂纹理 |

### 7.4 阈值后的形态学

阈值出来的二值图一定有噪点和小孔。下一步通常是形态学（第 4 篇），顺序一般是：

```
灰度图 → 滤波（可选）→ 阈值 → 开运算（去噪点）→ 闭运算（填孔）→ 连通域
```

## 9. 自测

**Q1**：直方图两端（0 和 255）都有很高的尖峰，说明什么？软件能救吗？

**Q2**：均衡化后标准差从 11.32 涨到 72.58，为什么熵反而略降？

**Q3**：CLAHE 的「限幅」限的是什么？为什么能压噪声？

**Q4**：`γ=0.45` 和「把图整体加 50」有什么区别？

**Q5**：Otsu 的 `η=0.912` 和 `η=0.692`，哪个分得好？为什么光照不均会让它下降？

**Q6**（换场景）：彩色图能不能直接对 BGR 三个通道分别做均衡化？会有什么问题？

### 答案

**A1**：同时存在过曝（255 堆积）和欠曝（0 堆积），动态范围不够。软件无法恢复已经截断的高光/阴影，只能改曝光或换 HDR。

**A2**：均衡化是单调映射，多个输入灰度会被合并到同一个输出灰度（量化），不同取值个数从 54 降到 48，离散熵因此略降。它提高的是动态范围，不是信息量。

**A3**：限的是每个直方图 bin 的高度（`clip × 平均高度`）。噪声让某个 bin 异常高，均衡时会被过度拉伸；削平后增益被限制，噪声不会被放大到极端。

**A4**：加常数是线性平移，会整体变亮并可能截断高光；伽马是非线性，主要提亮暗部、压缩亮部，高光更不容易溢出。

**A5**：`η=0.912` 分得好。光照不均让同一类（背景或零件）的灰度跨越很大范围，类内方差变大、类间方差占比下降，所以 `η` 降低，单阈值失效。

**A6**：可以，但会破坏颜色一致性：三个通道的 CDF 不同，均衡后比例变了，颜色会偏。正确做法是只对亮度通道（HSV 的 V、或 Lab 的 L）做均衡，色度保持不变。

## 10. 坑清单

| # | 坑 | 症状 | 处理 |
|---|---|---|---|
| 1 | 以为均衡化一定提高熵 | 指标对不上 | 看动态范围/标准差，不看熵 |
| 2 | 对彩色图逐通道均衡 | 颜色偏色 | 只对亮度通道做 |
| 3 | 均衡后再用固定阈值 | 阈值全变 | 重新标定，或改用 Otsu |
| 4 | CLAHE 的 tile 太小 | 块状伪影 | tile ≥ 8×8，开插值 |
| 5 | 相机 JPEG 上再做伽马 | 二次编码，对比度怪 | 确认是否已 sRGB |
| 6 | Otsu 用在光照不均 | 准确率骤降 | 局部阈值 / 光照校正 |
| 7 | 用最小/最大做拉伸 | 一个白点毁全图 | 用 1%/99% 分位数 |
| 8 | 阈值后不做形态学 | 噪点、孔洞多 | 开/闭运算 + 面积过滤 |
