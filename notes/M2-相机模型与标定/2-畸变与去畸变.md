## 0. 开始之前：任务与名词

### 0.1 任务：一张 1280×1024 的图，边缘直线弯了 28 像素

场景：用 8 mm 广角镜头拍一块标定板，板子铺满画面。看图像边缘，标定板的边肉眼可见地向内凹。

**痛点**：

- 直线测长：在边缘量的尺寸比中心短 3%，而且随位置变化。
- 拼接/测量：同一个工件移到画面边缘，尺寸就变了。
- 标定：如果不写畸变模型，重投影误差会在边缘系统性堆积，内参也跟着偏。

**本篇解决哪一步**：在「归一化坐标」这一层补上畸变，并讲清楚「去畸变」的方向和顺序。张正友怎么把 `k1,k2,p1,p2` 一起解出来，见第 3 篇。

### 0.2 名词卡片

**径向畸变（radial distortion）**
- 一句话：放大率随「离主点的距离」变化，导致同心圆方向上的压缩/拉伸。
- 数学：`x_d = x·(1 + k1·r² + k2·r⁴ + k3·r⁶)`。
- 不是：不是「模糊」。畸变是几何位置变了，清晰度不变。

**切向畸变（tangential distortion）**
- 一句话：镜头组与传感器不平行（装调偏心），导致图像「被斜着推了一下」。
- 数学：`x_d += 2p1xy + p2(r²+2x²)`，`y_d += p1(r²+2y²) + 2p2xy`。
- 不是：不是旋转。旋转可以用外参吸收，切向畸变不能。

**桶形畸变（barrel distortion）**
- 一句话：`k1 < 0`，边角被向中心压，直线向外鼓——像木桶的侧面。
- 表现：广角镜头最常见。

**枕形畸变（pincushion distortion）**
- 一句话：`k1 > 0`，边角被向外推，直线向内凹——像缝纫时绷紧的枕套。
- 表现：长焦镜头更容易出现。

**去畸变（undistortion / rectification）**
- 一句话：把「畸变图」重采样成「理想针孔图」。
- 关键：正向（理想 → 畸变）有闭式解，反向（畸变 → 理想）没有，只能迭代。

**新相机矩阵（new camera matrix）**
- 一句话：去畸变之后，那个「理想图」对应的 K。
- 用在哪：`cv2.getOptimalNewCameraMatrix` / `cv2.undistort` 的 `newCameraMatrix`。

## 1. 畸变从哪来：镜头不是针孔

针孔模型假设「所有光线严格穿过一个点」。真实镜头做不到：

| 物理原因 | 表现 | 模型里的项 |
|---|---|---|
| 球面透镜的边缘焦距与中心不同 | 放大率随半径变化 | 径向 `k1, k2, k3` |
| 多片镜片装调偏心、传感器不平行 | 图像被斜推一点 | 切向 `p1, p2` |
| 镜头太广（>90°） | 多项式模型不够用 | 换鱼眼模型（θ 多项式） |

```
理想点 (x, y)          归一化坐标，无量纲
    │
    ├─ 乘径向因子 (1 + k1 r² + k2 r⁴ + k3 r⁶)
    ├─ 加切向修正 (2p1xy + p2(r²+2x²), ...)
    ▼
畸变点 (x_d, y_d)
    │
    └─ 乘 K → 像素
```

**为什么写在归一化坐标上**：畸变是镜头属性，与「这张图多少像素」无关。同一支镜头换一台分辨率不同的相机，`k1,k2,p1,p2` 不变（K 变了）。如果把畸变定义在像素坐标上，换个分辨率就要重新标定，参数也没法互相比较。

## 2. 径向畸变：放大率随半径变

### 2.1 模型

```
r² = x² + y²
x_d = x · (1 + k1·r² + k2·r⁴ + k3·r⁶)
y_d = y · (1 + k1·r² + k2·r⁴ + k3·r⁶)
```

它是一个**只跟半径有关**的缩放因子。半径越远，`r²`、`r⁴` 越大，所以边缘效果最明显。

### 2.2 一组真实数字（本篇参数 `k1=-0.28, k2=+0.07`）

| 归一化半径 r | 径向因子 | 相对偏差 |
|---|---|---|
| 0.05 | 0.9993 | −0.07% |
| 0.10 | 0.9972 | −0.28% |
| 0.20 | 0.9889 | −1.11% |
| 0.30 | 0.9754 | −2.46% |
| 0.35 | 0.9668 | −3.32% |

**怎么读**：画面中心几乎不变，越往边角压缩越多。角上 `r=0.353` 时压了 3.3%。

换成像素（`fx = 2318.84`、1280×1024），四个角被拉走的距离：

```
(   0,   0): 27.23 px
(1279,   0): 29.26 px
(   0,1023): 26.15 px
(1279,1023): 28.18 px
```

四个角**不一样**（27.2 / 29.3 / 26.2 / 28.2）——这就是切向畸变存在的证据：纯径向的话四个角应该完全对称。

在 500 mm 处，28 px 相当于 `28 × 0.216 ≈ 6.0 mm`。你的公差如果是 0.05 mm，这就是 120 倍的误差。

## 3. 桶形 vs 枕形：只看 `k1` 的符号

| 参数 | 边角径向变化 | 直线形状 | 常见镜头 |
|---|---|---|---|
| `k1 < 0`（桶形） | −0.0123（向内） | 向外鼓 `+11.20 px` | 广角、手机主摄 |
| `k1 > 0`（枕形） | +0.0123（向外） | 向内凹 `−11.20 px` | 长焦、部分工业镜头 |

同一组参数只翻 `k1` 符号，位移量完全对称，**方向相反**。

**一眼分辨的方法**：把一张方格纸/棋盘格拍满画面，看最外一圈线。

- 线向外鼓（像木桶）→ 桶形 → `k1 < 0`。
- 线向内凹（像枕套）→ 枕形 → `k1 > 0`。

**为什么桶形更常见**：广角镜头的边缘放大率天然低于中心。这也是为什么鱼眼镜头（视角 > 120°）看起来像「球」。

## 4. 去畸变：正向有公式，反向只能迭代

### 4.1 两个方向不对称

```
正向：理想 (x,y) ──多项式──> 畸变 (x_d,y_d)      ✅ 闭式，一次算完
反向：畸变 (x_d,y_d) ──?──> 理想 (x,y)           ❌ 没有闭式解
```

因为反向要从 `x_d = x·f(x)` 里解出 `x`，而 `f` 本身依赖 `x`（`r² = x²+y²`），所以这是一个非线性方程。

### 4.2 不动点迭代

```
x ← (x_d − 切向项(x)) / 径向因子(x)
```

每迭代一次，用当前猜测重算一次修正量。k 越小收敛越快，边缘比中心慢。

实测（一个靠近边角的点，`r ≈ 0.30`）：

| 迭代次数 | 残余误差 |
|---|---|
| 1 | 0.778 px |
| 2 | 0.0410 px |
| 3 | 0.00216 px |
| 5 | 5.99e-06 px |
| 10 | 2.38e-12 px |

**工程结论**：3 次就到 0.002 px（远小于亚像素精度），10 次到浮点极限。OpenCV 默认用 5 次左右，广角镜头会更多。

### 4.3 实际怎么用

```python
# 离线：一次算好映射表，之后每帧 remap
map1, map2 = cv2.initUndistortRectifyMap(K, dist, None, newK, (w, h), cv2.CV_16SC2)
undist = cv2.remap(img, map1, map2, cv2.INTER_LINEAR)
```

**别每帧都调 `cv2.undistort`**：它内部也是建表 + `remap`，但每次都重建。实时系统里表只算一次。

## 5. 顺序：先畸变，再乘 K

这是本篇最容易写错、也最难查的一行。

### 5.1 正确顺序

```
1. 像素 → K⁻¹ → 归一化（畸变坐标）
2. 迭代去畸变 → 理想归一化坐标
3. 乘 K → 理想像素
```

### 5.2 错误顺序的代价

如果你先乘 K、再把「归一化单位」的修正量直接加到像素上（忘了乘 `fx`）：

```
正确: 先畸变再乘 K                 -> (1185.044, 938.774)
错误: 先乘 K 再加修正（没乘 fx）    -> (1199.994, 949.995)
                                    差 18.69 px
```

18.69 px 在 500 mm 处约 `4.0 mm`。**这个错误不会报错，只会让你的测量系统性偏。**

### 5.3 记住一句话

> 畸变永远定义在归一化坐标上；**任何以「像素」为单位的式子，都要先乘 `fx` 才能和畸变相加。**

## 6. 去畸变之后：视场变了，K 也变了

桶形畸变把边角向内压；去畸变是反方向，会把边角推回外面。结果：**理想图比原图大**。

实测（把畸变图的四个角反解）：

```
(   0,   0) -> (  -23.33,  -19.37)
(1279,   0) -> ( 1304.62,  -20.43)
(   0,1023) -> (  -22.63, 1041.16)
(1279,1023) -> ( 1303.91, 1042.21)

理想图跨度 1327.9 x 1062.6 px（原图 1279 x 1023）
要装下全部内容，需放大约 1.0388 倍
```

两个后果：

1. **黑边**：如果直接输出原尺寸，四个角会出现黑边（映射到图外）。
2. **K 变了**：缩放或裁剪之后，`fx, fy, cx, cy` 都要跟着改（第 1 篇 §6 的规则）。

OpenCV 用 `getOptimalNewCameraMatrix(K, dist, (w,h), alpha)` 帮你算这个「新 K」：

- `alpha=0`：裁掉所有无效像素，图像变小，**不保留黑边**（测量首选）。
- `alpha=1`：保留全部像素，图像变大，**有黑边**（可视化/后续拼接用）。

**工程建议**：做测量时固定用 `alpha=0`，并在标定报告里记下新的 K 和裁剪偏移，否则下次换代码就又对不上了。

## 7. 什么时候需要 `k3` / `p1` / `p2`

| 参数 | 何时需要 | 何时可以先不管 |
|---|---|---|
| `k1, k2` | 几乎所有镜头 | — |
| `k3` | 广角/鱼眼、边缘弯曲明显 | 普通工业镜头（FOV < 45°） |
| `p1, p2` | 装配偏心、边缘不对称（四个角位移不等） | 高质量定焦（切向 < 1 px） |
| 鱼眼模型 | FOV > 90°，多项式失效 | — |

**过参数化的风险**：参数越多，越容易把噪声拟合进去。判断标准不是「误差更小」，而是**独立数据上的误差是否也变小**（第 3 篇会讲交叉验证）。

**怎么判断要不要加 `p1,p2`**：看四个角的位移是否对称。本篇 27.23 / 29.26 / 26.15 / 28.18——不对称差 3 px，说明有切向成分；如果四个角完全一致，`p1=p2=0` 就够了。

## 9. 自测

**Q1**：径向畸变和切向畸变的物理原因分别是什么？各自用几个参数？

**Q2**：`k1 = -0.28`，这是桶形还是枕形？图像最外圈的直线会往哪边弯？

**Q3**：为什么「理想 → 畸变」可以一次算完，「畸变 → 理想」必须迭代？

**Q4**：去畸变之后直接用原来的 K 去算 `mm/px`，会有什么问题？

**Q5**：判断对错并说明原因：「畸变参数 `k1` 会随图像分辨率变化，所以换分辨率要重标。」

**Q6**（换场景）：一个 FOV 120° 的鱼眼相机，用 `k1,k2,k3` 三参数模型会怎样？

### 答案

**A1**：径向来自「边缘焦距与中心不同」（球面透镜），用 `k1,k2,k3`；切向来自「镜片装调偏心/传感器不平行」，用 `p1,p2`。径向只跟半径有关，切向跟方位有关。

**A2**：桶形（`k1<0`）。边角被向中心压，直线的两端比中间压得多，所以看起来**向外鼓**（本篇实测 `+11.20 px`）。

**A3**：正向是显式多项式，代入即得；反向要从 `x_d = x·(1+k1(x²+y²)+…)` 解 `x`，方程里 `x` 同时出现在两边，没有闭式解，只能用不动点迭代（或牛顿法）。

**A4**：去畸变会把图像放大（本例 1.0388 倍）或裁剪，`fx, cx, cy` 都变了。继续用原 K，`mm/px` 会偏 3.9%，所有尺寸系统性偏大。

**A5**：错。`k1,k2,p1,p2` 定义在**归一化坐标**上，与分辨率无关；变的是 K。换分辨率只需缩放 K，不用重标畸变（除非同时改了焦距/对焦）。

**A6**：多项式会失效。FOV 120° 时 `r` 很大，`k1 r² + k2 r⁴ + k3 r⁶` 会剧烈振荡甚至非单调，去畸变迭代不收敛。应该用鱼眼模型（`θ` 的多项式，OpenCV 的 `fisheye` 模块）。

### 10.1 主干（1 题）

**Q1. 为什么直线会被拍弯？畸变到底是什么？** ★

**一句话**：镜头的放大率不是常数，随「离主点的距离」变化，所以直线被映射成曲线。

**讲开**：

- 针孔模型假设「所有光线严格过一个点」，真实镜头做不到：边缘的等效焦距与中心不同。
- 于是同一个「归一化半径」在不同方向上被缩放得不一样，直线自然弯。
- 模型把它写成归一化坐标上的多项式：`x_d = x(1 + k1r² + k2r⁴ + k3r⁶)`，再加切向项。
- 关键认知：**畸变是几何，不是模糊**。图像依然清晰，只是位置错了。

**数字锚点**：本篇 `k1=-0.28, k2=0.07`，1280×1024 的四个角被拉走 26~29 px；500 mm 处约 6 mm。

**追问**：「那为什么不用一个『完美镜头』？」→ 物理上做不到；FOV 越大越难，所以工程上选择「标定 + 校正」。

### 10.2 两个方向 + 两个形状（4 题）

**Q2. 径向畸变和切向畸变，分别是什么原因、什么表现？** ★

**一句话**：径向是「放大率随半径变」，切向是「镜片装歪了」，前者对称、后者不对称。

**讲开**：

- 径向：`r_d = r(1 + k1r² + k2r⁴)`，只跟距离有关，四个角对称地动。
- 切向：`x_d += 2p1xy + p2(r²+2x²)`，跟方位有关，四个角位移**不相等**。
- 判别方法：量四个角的位移。本例 27.23 / 29.26 / 26.15 / 28.18，差 3 px → 有切向成分。
- 标定时如果只估 `k1,k2`，切向误差会全部堆进重投影残差，表现为「边缘残差方向一致」。

**数字锚点**：四角位移分别为 27.23 / 29.26 / 26.15 / 28.18 px——不一致就是切向。

**追问**：「切向能不能用外参吸收？」→ 不能。外参是刚体变换（旋转+平移），切向是随位置变化的非线性偏移。

**Q3. 桶形和枕形怎么区分？** ★

**一句话**：看最外圈直线——向外鼓是桶形（`k1<0`），向内凹是枕形（`k1>0`）。

**讲开**：

- 桶形：`k1<0`，半径越大压得越狠，边角向内、直线向外鼓。
- 枕形：`k1>0`，边角被向外推，直线向内凹。
- 现实分布：广角/手机主摄多为桶形；长焦容易出现枕形。
- 记忆法：木桶的板是向外鼓的。

**数字锚点**：只翻 `k1` 符号，边角径向变化从 `−0.0123` 变 `+0.0123`，直线弯曲从 `+11.20` 变 `−11.20 px`。

**追问**：「有没有可能同时有？ 」→ 有，`k1` 与 `k3` 反号时会出现「桶形 + 枕形」混合（边缘又鼓又凹），鱼眼更常见。

**Q4. 畸变参数为什么定义在归一化坐标，而不是像素坐标？** ★★

**一句话**：归一化坐标只跟镜头有关，像素只跟传感器分辨率有关；这样参数才能跨相机复用。

**讲开**：

- 归一化坐标是「方向」，与分辨率无关；`k1` 描述的是镜头的角度响应。
- 如果定义在像素域，换个分辨率 `k1` 就要变（差一个 `fx²` 的量级），参数表没法通用。
- 同样地，`p1,p2` 也定义在归一化域，单位与 `k` 一致。
- 调试技巧：把畸变位移乘以 `fx` 才是像素，任何时候看到「像素 + 归一化量」相加，都是 bug。

**数字锚点**：同一支 8 mm 镜头，3.45 µm 像元 `fx=2318.84`；5.5 µm 像元 `fx=1454.5`——`k1` 不变，K 变了。

**追问**：「那标定出来的 `k1` 能在别的镜头上用吗？」→ 不能，只对同一支镜头（同一焦距、同一对焦位置）有效。

**Q5. 去畸变为什么必须迭代？迭代几次够？** ★★

**一句话**：反向方程里未知数在两边，只能不动点迭代；3 次到 0.002 px，5~10 次到极限。

**讲开**：

- 正向 `x_d = x·f(x)` 是显式多项式，代入即得。
- 反向要从 `x_d = x·f(x)` 解 `x`，而 `f` 依赖 `x`，无闭式解。
- 不动点迭代：`x ← (x_d − 切向项)/径向因子`，每次用当前猜测重算修正量。
- 收敛速度取决于 `|k1|·r²`：越靠近边缘越慢，广角镜头要多迭代几次。

**数字锚点**：迭代 1/2/3/5/10 次的残余 = 0.778 / 0.0410 / 0.00216 / 5.99e-06 / 2.38e-12 px。

**追问**：「能不能用牛顿法？」→ 可以，收敛更快，但每次要算雅可比；工程上不动点迭代已经够用。

### 10.3 四个坑（4 题）

**Q6. 去畸变和乘 K，顺序能不能反？** ★★

**一句话**：不能。畸变定义在归一化坐标，先乘 K 再减畸变（没乘 `fx`）会差 18+ 像素。

**讲开**：

- 正确：像素 → `K⁻¹` → 归一化（畸变坐标）→ 迭代去畸变 → 乘 `K` → 像素。
- 错误：先乘 K 得到像素，再把「归一化单位」的修正量直接加上去——漏了 `fx`。
- 后果不是报错，而是**系统性偏移**：所有点一起偏，看起来像「标定不准」。
- 判断方法：用合成数据做「投影—反投影」往返，误差应在 `1e-12` 量级；如果到 `1e-1`，就是单位/顺序错。

**数字锚点**：正确 `(1185.044, 938.774)`，错误 `(1199.994, 949.995)`，差 **18.69 px**（500 mm 处约 4 mm）。

**追问**：「OpenCV 的 `undistort` 是怎么做的？」→ 内部先建 `initUndistortRectifyMap`（对每个输出像素反解），再 `remap`；本质上就是「反向迭代 + 查表」。

**Q7. 去畸变之后，原来的 K 还能用吗？** ★★

**一句话**：不能。理想图被放大（本例 1.0388 倍）或裁剪，`fx, fy, cx, cy` 都变了。

**讲开**：

- 桶形去畸变会把边角推回原图之外，整幅图「变大」，四角出现黑边。
- `alpha=0` 裁掉黑边：图像变小，K 要乘缩放并减偏移；`alpha=1` 保留：K 也要变。
- 忘了更新 K，`mm/px` 会偏 3.9%，尺寸系统性偏大。
- 工程上把这个「新 K」写进配置，而不是每次运行时现算。

**数字锚点**：四角去畸变后落在 `(-23.3,-19.4)` 到 `(1304.6, 1042.2)`，跨度 `1327.9 × 1062.6`，原图 `1279 × 1023`，需要放大 **1.0388** 倍。

**追问**：「为什么要用 `getOptimalNewCameraMatrix` 而不是手动放大？」→ 它会同时考虑黑边、主点偏移和纵横比，手算容易漏项。

**Q8. `k3`、`p1`、`p2` 什么时候该加？加多了会怎样？** ★★★

**一句话**：边缘明显弯曲才加 `k3`，四角不对称才加 `p1,p2`；加多了会拟合噪声。

**讲开**：

- 普通工业镜头（FOV < 45°）：`k1,k2` 足够，`k3` 加了也估不准（数据里没有信息）。
- 广角/鱼眼：不加 `k3` 边缘会残留几像素的弯。
- 切向：四角位移不对称才需要，对称就说明没有。
- 判断标准不是「训练误差更小」，而是**在没参与标定的图上误差也小**（留一法/另一组图）。

**数字锚点**：本例四角位移 27.23/29.26/26.15/28.18，不对称差 3 px → 值得加 `p1,p2`；如果四角差 < 0.5 px，可以直接设 0。

**追问**：「那鱼眼怎么办？」→ 换 `fisheye` 模型（`θ` 多项式），`k1..k3` 在 120° 以上会振荡、迭代不收敛。

**Q9. 去畸变后边缘出现黑边/锯齿，怎么处理？** ★★

**一句话**：黑边是「映射到图外」，锯齿是「重采样没插值好」；用 `newCameraMatrix` + 双线性/双三次 `remap`。

**讲开**：

- 黑边：输出图里存在「原图没有覆盖」的区域，值只能是 0。用 `alpha=0` 裁掉，或 `alpha=1` 接受黑边。
- 锯齿/摩尔纹：`remap` 用最近邻会出锯齿，双线性是默认，亚像素测量用双三次更稳。
- 另一个坑：**先去畸变再缩小**，不要先缩小再去畸变——缩小会先把畸变的采样信息抹掉。
- 测量场景：去畸变 → 裁 ROI → 亚像素边缘，顺序不能反。

**数字锚点**：本例需要放大 1.0388 倍才能装下全部内容；`alpha=0` 时图像会缩到约 96% 的有效区域。

**追问**：「黑边会影响标定吗？」→ 会。黑边像素是常量 0，参与重投影会把残差拉偏；标定只用有效区域。

**Q10.（补）为什么工业上「先标定再测量」，而不是「先测量再校正」？** ★★

**一句话**：校正需要 K 和畸变参数，而这两样只能由标定给出；没有它们，测出来的尺寸没有物理意义。

**讲开**：

- 测量输出是像素，要变成毫米必须有 `mm/px = Z/fx`；`fx` 来自标定。
- 边缘位置的畸变误差是**系统性的**，不能靠平均消除。
- 所以标准流程是：标定（K + dist）→ 去畸变 → 测量 → 用新 K 换算。
- 反过来「先测再校正」等于在错误坐标里做几何，残差会混在一起，无法分离。

**数字锚点**：28 px 的畸变在 500 mm 处约 6 mm，而典型公差是 0.05 mm——差两个数量级。

**追问**：「标定一次能用多久？」→ 只要不改焦距/对焦/分辨率/安装，可以长期用；但温度变化会让主点漂移，精密测量建议定期复标。

---

> **只背 3 道**：Q1（畸变是什么）、Q2（径向 vs 切向）、Q3（桶形 vs 枕形）。这三道决定你能不能「看图说病因」。

## 11. 坑清单

| # | 坑 | 症状 | 处理 |
|---|---|---|---|
| 1 | 把畸变定义在像素域 | 换分辨率参数就失效 | 定义在归一化坐标，用时乘 `fx` |
| 2 | 先乘 K 再加畸变修正 | 系统性偏 18+ px | 先畸变，再乘 K |
| 3 | 去畸变只迭代 1 次 | 边缘残留 0.8 px | 至少 3~5 次，广角更多 |
| 4 | 去畸变后不更新 K | `mm/px` 偏 3.9% | 用 `getOptimalNewCameraMatrix` |
| 5 | 黑边像素参与标定/测量 | 残差被拉偏 | 只用有效区域，或 `alpha=0` |
| 6 | 四角不对称还只估 `k1,k2` | 边缘残差方向一致 | 加 `p1,p2` |
| 7 | 鱼眼用多项式模型 | 迭代不收敛、振荡 | 换 `fisheye` 模型 |
| 8 | 先缩小再去畸变 | 细节丢失、摩尔纹 | 先去畸变再缩放 |
| 9 | 每帧重建映射表 | 帧率上不去 | `initUndistortRectifyMap` 只算一次 |
| 10 | 标定图不覆盖边缘 | `k1` 估不准 | 标定板拍满画面、覆盖四角 |
